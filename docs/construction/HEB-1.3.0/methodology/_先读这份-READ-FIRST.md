# 先读这份 · READ AI FIRST

> **本目录 = 方法论本体（`methodology/`）。**
> 它**跨任务复用**：整个文件夹拷到另一个任务旁边，**无需改动即可用**。
> 任务专属的东西（总蓝图、阶段蓝图、完成报告、决策、人工台账）放在**同级的 `task-<任务名>/`** 里——
> 那个目录**不随本包分发**，用本目录的三份模板新建（见 §三.1）。

```
<工作根目录>\
├── methodology\          ← 本目录：规范 / 经验库 / 回写规范 / 三份模板（跨任务复用，共 9 份）

                            总蓝图 / 阶段蓝图 / 完成报告 / 决策 / 人工台账
```

**分级判据（自评问句）**：

```
换一种语言还成立吗？      是 → H（跨环境通用，写蓝图前必读）
换同类框架还成立吗？      是 → M（同类系统通用，写蓝图前必读）；否 → L
核心是命令 / API 行为吗？ 是 → L（绑定技术栈，按栈检索，不通读）
```

> ⚠️ **不要把具体结论当通用知识套用**：L 级条目里的命令与 API 结论**只在那套技术栈成立**，
> 换栈后重新验证。这正是拆成两库的原因。

## 四、三点须知

1. **本包不含任何指向包外文件的链接**：跨目录引用一律是相对路径（`methodology/…`、`../task-<任务名>/…`），
   任务侧的文件用**占位符**，引用历史记录只写「记录标识」。因此 `methodology/` 可以直接转发，
   也可以整份拷到任何任务旁边——**不会因为换目录而断链**。
   ⚠️ 例外：少数「环境类」条目含**原机器的绝对路径**（如 `D:\data\node24\npx.cmd`），那是历史记录原文，**当举例看、不要照抄**。
2. **经验条目自身是完整的**（错误做法 / 症状 / 根因 / 正确做法 四段齐全）。
   出处只承担"溯源"与"唯一标识"两个作用——不去解析它，经验库照样可用。
3. **要迁移到你自己的项目**时：用规范 §1–§10 全部 + 通用经验库（H/M）全部 + 具体坑库**只取形状**。
   具体条目多为 Node / Electron / git 场景，**参考形状、别照抄结论**。
