# Phase N 施工蓝图：<名称>

> **执行者**：agent。本文件自包含，不需要对话历史即可执行。
> **风险等级**：零 / 低 / 中 / 高
> **预计耗时**：N–M 分钟
> **文档规范**：见 `../methodology/BLUEPRINT-撰写规范.md` §4
> **前置**：依赖哪个 Phase 的什么产物

> ⚠️ **（可选但推荐）本 Phase 的做法已被实测推翻并替换** —— 若原计划被实测推翻，在标题下方写清
> 「原计划 / 实测结论 / 新做法 / 证据见第几节」，并明确「执行者请按本文档执行，不要按旧版描述执行」。

## 一、施工目标

- 核心问题（带 `file:line` 根因）
- 目标清单（可勾选）
- **非目标（明确不做）** ← 防止 agent 过度施工，必须有「为什么」和「何时做」

## 二、实测证据（决定本 Phase 做法，执行前请读）★

- 支撑本 Phase 决策的**实测数字**，不是推断
- **被推翻的原计划**：列出试过什么、结果如何、为什么不用它
- 每条证据标明：在哪测的（沙箱 / 真机）、怎么复现

## 三、前置条件与停止条件

- 前置：可执行命令 + 期望值；不满足则**不得开始**
- ★ **上阶段回写清单无未勾选项**：
  ```powershell
  Select-String -Path "..\task-<任务名>\PHASE-<n-1>-完成报告.md" -Pattern '^\s*-\s*\[ \]|\|\s*\[ \]\s*\|'
  # 期望：无输出
  ```
- 停止：出现什么情况**立即停止并报告**，并写清「为什么必须停」

## 四、改动清单（Agent 直接执行）

- 逐条：文件路径 + 行号 + 改什么 + 为什么
- 逐项依据（已实测，非推断）
- 标注「**必改且编译器不会提醒你**」的陷阱
- 顺序敏感的操作**显式写明顺序及其理由**

## 五、人工环节 ★（人必须做的部分；自 Phase 5 起必备）

> **一个环节一行，全部写进 `../task-<任务名>/HUMAN-人工验证台账.md`**（规范 §4.1.2 的九列表）：
> 「要验什么 / 期望值 / 证据」三列由 **agent 预填**，人只填后三列。**本蓝图不另开作业单或回执文件。**

- **H-A 阻塞性拍板**（开工前；未答复不得开始 —— 同时登记进 §三 前置条件；台账里以 `[ ]` / `[x]` 表达）
- **H-B 完工评审**（本 Phase 的退出条件；人只做判断项，**不重算脚本能算的数**）
- **H-C 待验项登记**（本 Phase 验不了的，追加进 `HUMAN-人工验证台账.md` 的一行）
- 本 Phase 明确**不需要**人做的事（防止让人做无用功）

> 四条纪律：人只做机器做不了的事；期望值由 agent 预先算出；验不了就明说并登记；
> **不得为了凑内容发明无用的人工步骤**（让人去点一个跑不起来的程序是负价值）。
> 逐条写法与判据设计八条硬要求见规范 §4.1；**验完在台账里就地把那一行回填**（规范 §4.1.3）。
