# 修正回写规范与清单模板

> **文档定位**：本文件是 [BLUEPRINT-撰写规范.md](BLUEPRINT-撰写规范.md) **§5.1** 的完整展开。
> 读者：**写完成报告的人 / 执行阶段的人**。位于 `methodology/`（方法论，跨任务复用）。
>
> **一句话**：**修正不能只活在报告里；主蓝图永远是最新口径。**

---

## 一、要解决的问题

实战里的真实病灶：

| 现象 | 后果 |
|---|---|
| P2 报告里查出两处错误（类别 C 从 0 改成 5；`merge-tree` 必须先物化工作区），但"按项目所有者决定，既有蓝图文档未作修改" | P3/P4/P5 每份报告都得写一句「**必须先读 P2 报告第二节**，不要沿用总蓝图的旧说法」 |
| 修正只写在完成报告的「关键偏差」节 | 后续 Phase 要**翻遍所有旧报告**才知道该按哪版执行 |
| 基线数值在报告里被改写，总蓝图还留着旧值 | 两处不一致，执行者不知道信哪个 |

**结论**：报告的读者是"下一个 Phase"，而总蓝图才是"每个 Phase 都会拿到的那一份"。
**修正在哪被用到，就要回到哪。**

---

## 二、触发条件（任一出现即**必须**回写）

| 编号 | 触发条件 | 判定问法 |
|---|---|---|
| **T1** | **判据被修正** | 验收标准本身改了？（旧判据结构上做不到、或与步骤自相矛盾、或把正常行为判成失败） |
| **T2** | **基线数值被改写** | 总蓝图「当前基线」里的任何数字变了？（HEAD / 冲突数 / 命中数 / 索引条数 / 版本号…） |
| **T3** | **蓝图描述被实测推翻** | 蓝图里的做法、拓扑、分类、命令，被实测证明是错的？ |
| **T4** | **新增一条经验** | 踩到新坑、或发现某条旧认知不成立？ |

> **无触发也要写"无"**，不许留空——留空等于没检查。

---

## 三、回写目标（写到哪里）

| 触发 | 回写目标 | 具体动作 |
|---|---|---|
| **T1** | **判据台账**（总蓝图 §9.1，或该任务的独立台账） | 追加一行：`编号 / 旧判据 / 新判据 / 依据（哪份报告的哪条偏差）/ 生效范围` |
| **T2** | 总蓝图「**当前基线**」 | 写新值；**旧值移入「历史基线（仅存档）」** |
| **T3** | 总蓝图**对应节** | 就地改正 + 保留「**曾错、已修正**」说明（含依据报告与偏差编号） |
| **T4** | **经验库**（按迁移性归位） | H/M → `BLUEPRINT-经验库-通用.md`；L → `BLUEPRINT-经验库-具体坑.md`；五元组 + 键号续编 + 标明等级（同时可在 `BLUEPRINT-经验库-全量台账.md` 留全量条目） |

**三条硬规则**：

1. **回写只「新增 + 标注」，不静默删除。** 旧值留在原地，或移入「历史基线（仅存档）」段。
   删除会让后人失去"曾经错过什么"的信息——那条信息本身就是可信度的一部分。
2. **回写要带依据**：每条回写都写清"依据哪份报告的哪条偏差"，否则后人无法判断该不该信。
3. **回写权不因"文档已冻结"而豁免**：只要后续 Phase 还会读它，就必须回写。

## 四、动作：完成报告末尾的「回写清单」

**四列，缺一不可**：

```markdown
## 十、回写清单 ★（未勾完不得提交）

| 触发条件 | 回写目标 | 回写内容一句话 | 已勾选 |
|---|---|---|---|
| T1 判据被修正 | 总蓝图 §9 判据台账 | J-04：`UU` 计数判据由"= 26"改为"= 26 且 UD/DU 均为 0" | [x] |
| T2 基线数值被改写 | 总蓝图 §九「当前基线」 | 冲突数 46 → 26；旧值已移入「历史基线（P3 之后）」 | [x] |
| T3 蓝图描述被推翻 | 总蓝图 §一 关键拓扑 | 原文"C 类 = 0"已改为 5，并标注「曾错、已修正，依据 P2 报告偏差 2」 | [x] |
| T4 新增一条经验 | `经验库-具体坑.md` §1 git | 新增 L 级条目：`merge-tree` 对 `HEAD` 测退化为 0 冲突（键号续编） | [x] |
| — | — | 本 Phase 无其他触发（已逐条核对 T1–T4） | [x] |
```

**「已勾选」列的取值**：`[x]` 已回写 / `[ ]` 未回写。
**存在任何 `[ ]` → 本阶段不得提交、不得宣告完成。**

## 五、下阶段的前置条件（可执行验证）

阶段蓝图的「三、前置条件」必须加一条，且**给命令**：

```powershell
# 上阶段回写清单无未勾选项 —— 应无输出
Select-String -Path "..\task-<任务名>\PHASE-<上阶段>-完成报告.md" -Pattern '^\s*-\s*\[ \]|\|\s*\[ \]\s*\|'
```

- **应无输出**。有输出 → 停下，先补回写，再开工。
- 报告用四列表时，未勾选项写成 `[ ]`（不是 `☐`、不是空），保证上面这条命令能抓到。
- 该检查同时覆盖报告里的其他可勾选项（若你把目标清单写成 `- [ ]` 形式，提交前也应全部闭合）。

## 六、验收（怎么知道回写做对了）

| 验收项 | 怎么验 |
|---|---|
| 新会话**只读「规范 + 总蓝图 + 本阶段蓝图」即可正确执行** | 让一个无对话历史的 agent 只拿这三份开工，观察它是否要问"按哪版执行" |
| **无需回头读任何旧阶段报告来纠正口径** | 在总蓝图里 grep 上阶段的偏差结论 → 应已就地反映（不是仅以链接形式指向报告） |
| 旧值没被静默删除 | 总蓝图里 `历史基线（仅存档）` 段存在且非空 |
| 经验库归位正确 | 新增条目落在通用库（H/M）或具体坑库（L），不是随手塞进报告 |

## 七、与「人工验证台账」的分工（别混）

| 台账 | 管什么 | 编号 | 放哪 |
|---|---|---|---|
| **判据台账**（本文件 T1） | **按哪版验收** | `J-nn` | 总蓝图 §9.1 或任务目录内独立台账 |
| **人工验证台账** | **还欠哪些人要做的事**（拍板 / 评审 / 待验**共用一张九列表**；验完**就地回填那一行**，**不另建作业单或回执**，规范 §4.1.2–4.1.3） | `H-nn` | `task-<任务名>/HUMAN-人工验证台账.md` |
| **经验库**（本文件 T4） | **下次别踩同一个坑** | 键号 `C1 / D13 / A14 / R140…` | `methodology/BLUEPRINT-经验库-*.md` |

三者都要有，互不替代。

> **两条前置检查（v2.4.1 起，写进每个阶段蓝图的「三、前置条件」）**：
> ① 上阶段**回写清单**无未勾选项；② 上阶段**人工验证台账**无未闭合拍板（`[ ]`）。
> 命令见规范 §4.1.3（作用域已限定为 `^\|.*\[ \]`，**不会命中判据自己的原文**）。
