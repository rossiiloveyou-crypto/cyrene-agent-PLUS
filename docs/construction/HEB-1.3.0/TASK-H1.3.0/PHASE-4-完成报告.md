### 11.11 本 Phase 自己踩到并处置的一个坑（如实记录）

`git rev-parse --verify --quiet 'HEAD^1:<path>'` 在 PowerShell 里被**单引号**包住时，`^` **不被转义**且整串被当成一个参数传给 `--verify` ⇒ **返回 128（"cannot change to ..."）**，而 PowerShell 的 `if ($a -notmatch 'fatal')` 写法会把**多行 stderr 数组**判成真 ⇒ **一度得出"我方分支从未有过这 4 个文件"的错误中间结论**。
**处置**：改用 `git cat-file -e '<rev>:<path>'` + 显式 `$LASTEXITCODE`，并**用 node 脚本重跑全量判定**（`p4-probe-src-loss.mjs`）⇒ 得到正确结论（我方**有过**这 4 个文件，在 `598dfb75` 删除）。
**教训**：**"命令返回非 0"与"路径不存在"是两件事**（判据 **C49** 家族：命令成功 ≠ 事情做对了；这里反过来是**命令失败 ≠ 结论成立**）。
