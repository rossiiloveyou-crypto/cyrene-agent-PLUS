# 投喂说明 · 先读我

> 本文件有两个用途：**① 你把它整段复制粘贴给 AI**（新会话的第一句话）；
> **② AI 读它来决定该打开包里的哪几个文件。**

---

## 一、给使用者：怎么投喂

| 你在用什么 | 怎么给 |
|---|---|
| **CLI agent**（能读本地文件） | 把 `methodology\` 文件夹的路径给它 + 粘贴下面第二节 |
| **网页版 AI**（不能读本地文件夹） | 上传 `methodology\` 里的**前三份**（`_先读这份-READ-FIRST.md` + `BLUEPRINT-撰写规范.md` + `BLUEPRINT-经验库-通用.md`）+ 粘贴下面第二节 |
| **任何情况** | ⚠️ 只给 `methodology\`（9 份，合计约 **13 万 token**），**并让它按最小必读集只读 2–3 份**——不要一次全传 |

经验条目「出处」里提到的原始施工记录**不随本包分发**，也不必去找：出处只用于溯源，条目自身四段齐全。

---

## 二、直接复制这段给 AI

> 下面整段（含标题）复制。尖括号 "`<…>`" 换成你自己的内容。

```
你现在要读的是一套「让 AI agent 写出可执行蓝图」的方法论工具包，不是要执行的任务。

【第一步：按角色取最小必读集，不要通读整个文件夹】
- 先读：methodology\_先读这份-READ-FIRST.md        ← 它按你的角色给最小必读集，照着读即可
- 必读：methodology\BLUEPRINT-撰写规范.md           ← 写作规范（蓝图 12 节 / 完成报告 10 节 / 回写）
- 必读：methodology\BLUEPRINT-经验库-通用.md        ← H/M 级经验（跨语言、跨同类系统仍成立），先看 §0 场景索引
- 按需：methodology\BLUEPRINT-经验库-具体坑.md      ← L 级经验，**只查我这个技术栈的那一章**，不要通读
- 按需：methodology\BLUEPRINT-回写规范与清单模板.md   ← 只在我要写完成报告 / 要回写修正时读
- 按需：methodology\模板-总蓝图.md / 模板-施工蓝图.md / 模板-完成报告.md  ← 起草时直接抄骨架
- 按需：task-<任务名>\HUMAN-人工验证台账.md         ← 只在涉及人工环节时读（该任务目录由我自己建）；
                                                    人工验证**只写这一个文件**：一个环节一行，验完就地回填，不要另建作业单或回执
- 不要读：methodology\BLUEPRINT-经验库-全量台账.md   ← 约 **6 万 token**，只在要追溯某条经验的出处时用关键词定位
- 说明：经验条目「出处」里的原始文档不随包分发，不必去找它们

【第二步：确认我要你做什么】我选（<在这里填 A / B / C / D>）：

A. 用这套规范帮我【写蓝图】
   我的任务背景：<一句话说明>
   我已有的材料：<总蓝图 / 上一阶段文档 / 需求说明 …… 或"只有上面这些">

B. 用这套规范帮我【执行一份已有的蓝图】
   蓝图文件：<路径或内容>
   注意：执行时我不需要你读规范全文，只需规范 §4（蓝图结构）、§5（完成报告结构）、§8（施工记录）、
        §10 的 T1–T4（回写）

C. 把这套方法论【迁移到我的项目】（我不用它原本那套施工记录）
   我的项目：<一句话说明>
   请只取通用的部分：规范 §1–§10 全部 + methodology\BLUEPRINT-经验库-通用.md（H/M）全部 +
   methodology\BLUEPRINT-经验库-具体坑.md 里只取"形状"、不要照抄结论

D. 帮我【查证/追溯】某条经验
   键号或关键词：<例如 R140、或"向量没删干净">

【硬要求】
1. 先告诉我你打算读哪几个文件、为什么；我确认后你再读
2. 读完先复述你对任务的理解，再动手
3. 引用经验时用它的键号（如 C7 / D13 / A14 / R140），不要自己重编号
4. 如果你判断某条规范或经验与我的实际情况不符，直接指出，不要照搬
5. 写完成报告时，末尾必须有「回写清单」（T1–T4，四列表），未勾完不得提交
```

## 三、给 AI：本包的读取规则

**包内两块内容，用途不同**：

| 目录 | 用途 | 怎么读 |
|---|---|---|
| `methodology\` | **方法论本体**（规范 / 回写规范 / 3 个经验库 / 3 个模板 / READ-FIRST），共 **9 份** | **按角色读 2–3 份**（见下）。整体**跨任务复用**，可单独分享 |
| `README.md` · `投喂说明-先读我.md` | 给人看的说明（在**包根目录**；`README.md` 是 GitHub 自动渲染的那一份） | 人读 |

> **本包不附带两样东西**：任务目录 `task-<任务名>\`（用 `methodology\` 里的三份模板在**同级新建**，
> 见 READ-FIRST §三.1），以及经验的原始存档（出处只是**记录标识**，不需要、也无法在本包里打开）。

**最小读取集（覆盖 95% 的使用场景）**：

```
methodology\_先读这份-READ-FIRST.md          ← 先读它，它决定你还要读哪几份
methodology\BLUEPRINT-撰写规范.md
methodology\BLUEPRINT-经验库-通用.md
```

这三份合计约 **4.5 万 token**（通用库已扩到 106 条）。**先读它们，再决定要不要读其余的**；通用库请**先查 §0 场景索引**，命中再展开单条。

**其余几份什么时候读**：

| 文件 | 什么时候需要 |
|---|---|
| `methodology\BLUEPRINT-经验库-具体坑.md` | 要知道**你这个技术栈**的具体坑（按栈分章，**只查那一章**） |
| `methodology\BLUEPRINT-经验库-全量台账.md` | 要追溯某条经验的出处标识、看类型分布与"最珍贵的 10 条"（约 **6 万 token**，用关键词定位，别整份读） |
| `methodology\BLUEPRINT-回写规范与清单模板.md` | 要**写完成报告**、或要决定某条修正该回写到哪 |
| `methodology\模板-总蓝图.md` / `模板-施工蓝图.md` / `模板-完成报告.md` | 要起草时直接抄骨架（总蓝图 10 区块 / 阶段蓝图 12 节 / 完成报告 10 节） |
| `task-<任务名>\BLUEPRINT-总蓝图.md` | **你自己任务**的总蓝图——本包**不附带**任何范例任务的蓝图，该目录由你新建 |
| `task-<任务名>\HUMAN-人工验证台账.md` | 涉及**人工环节**时（由你新建，**开工前就把表头建好**）。它是人工验证的**唯一载体**：H-A 拍板 / H-B 评审 / H-C 待验**共用一张九列表**，一个环节一行；「要验什么 / 期望值 / 证据」由 agent 预填，人只填后三列，**验完就地回填，不再新建作业单或回执文件**（规范 §4.1.2 / §4.1.3） |

**经验分级（决定你怎么读）**：

```
H  换语言/框架仍成立     → methodology\BLUEPRINT-经验库-通用.md   写蓝图前必读
M  换同类系统仍成立      → methodology\BLUEPRINT-经验库-通用.md   写蓝图前必读
L  绑定具体命令/API      → methodology\BLUEPRINT-经验库-具体坑.md  按当前技术栈检索，不通读
```

**出处怎么读**（经验条目的末列）：

```
引用写法①：SELF-update 260925/phase3-p3-erasure-and-console.md:1622-1646   ← 原始施工记录（未随本包分发）
引用写法②：../methodology/BLUEPRINT-撰写规范.md                            ← 包内相对路径，直接可解析

「出处」不是链接：它标识"这条经验当时从哪份记录的哪几行抽出来"；
那批原始文档不在本包里，不用去找。引用某条经验时用它的键号（C7 / D13 / R140…）。
```

本包内的跨目录引用（`methodology/…`、`../task-<任务名>/…`）**全部可解析**——任务侧一律写成占位符。

**两点提醒**：

1. **本包不含任何指向包外文件的链接**：跨目录引用一律是相对路径（`methodology/…`、`../task-<任务名>/…`），
   任务侧用占位符——`methodology\` 可以整份拷到任何任务旁边，也能直接转发。
   ⚠️ 少数环境类条目会引用**原机器的绝对路径**（如 `D:\data\node24\npx.cmd`）作为历史记录原文：**当举例看，不要照抄执行**。
2. **经验条目本身是完整的**（错误做法 / 症状 / 根因 / 正确做法 四段都写在条目里）。
   不去解析任何出处，经验库照样可用——出处只承担"溯源"与"唯一标识"两个作用。

## 四、五个角色读的不是同一批文件（最容易搞混）

| 角色 | 读什么 | 产出 |
|---|---|---|
| **写蓝图的人 / agent** | 撰写规范 + 经验库-通用 + 该任务总蓝图 + 上阶段报告的「关键偏差」与「回写清单」 | 下一份 **阶段蓝图** |
| **执行蓝图的人 / agent** | 该任务总蓝图 + 该阶段蓝图（**只需这两个**；规范只查 §4/§5/§8/§10 相关节） | 执行结果 + **完成报告** |
| **写报告的人 / agent** | 同上 + `BLUEPRINT-回写规范与清单模板.md` | 完成报告 + **回写清单** |
| **写总蓝图的人 / agent** | 规范 §6 + 全部阶段报告的「关键偏差」与「回写清单」 | 总蓝图的更新 |
| **复核的人 / agent**（撰写者） | 规范 §5.2 + 本阶段完成报告 + 总蓝图相关节 | 报告里的「**撰写者复核补正**」一节 + 新的 `H-nn` |

执行者**不需要**规范与经验库全文。

## 五、三条纪律（v2.2 新增，别漏）

1. **跨目录引用一律用相对路径**（`../methodology/…`、`../task-<任务名>/…`），**不写裸文件名**——
   裸文件名换目录后必然断链。
2. **写完报告要回写**：T1 判据被修正 → 判据台账；T2 基线被改写 → 总蓝图「当前基线」（旧值移入历史）；
   T3 蓝图被实测推翻 → 总蓝图对应节；T4 新增经验 → 经验库（按 H/M/L 归位）。
   **「回写清单」四列表未勾完，不得提交、不得宣告完成。**
3. **回写只「新增 + 标注」，不静默删除**——旧值留在原地或移入「历史基线（仅存档）」。
4. **人工验证只有一个文件**（v2.4.1）：`task-<任务名>\HUMAN-人工验证台账.md`。
   一个环节一行；**验完就地回填那一行**，不要新建"验证作业单""验证回执"之类的文件；
   下一阶段开工前查两条：**回写清单无未勾项** + **台账无未闭合拍板**（规范 §4.1.3 给了命令）。
