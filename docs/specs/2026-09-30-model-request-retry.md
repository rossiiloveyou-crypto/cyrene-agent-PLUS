# 主模型请求重试设计

## 目标与范围

在“设置 → 模型设置 → 运行设置”增加全局“重试次数”，默认 5，范围 0–10。这里的次数是**首次请求失败后允许的额外尝试次数**；0 表示关闭，5 表示同一模型操作最多重试 5 次。设置保存后，新开始的运行读取快照；已经运行的对话不随设置变更而改动。

覆盖聊天模式的回复生成、工作模式的每轮主模型调用和工作模式的历史压缩摘要。一个工作运行中的每轮模型调用各自有预算；工具执行重试、视觉模型、嵌入、插件等调用沿用原策略。离线待发队列和无限重试不在本期范围。

与 ZCode 对齐的是有限重试、按错误类型区分、指数等待、服务端建议等待时间、可取消等待和前端进度。ZCode 的流中断安全锚点续接需要重建上下文与去重，本期不实现：只要当前模型操作已有任何流式文本或推理增量，就不自动重发该操作。

## 复用与边界

- 复用 `src/main/orchestrator/vendors/model-error-classifier.ts` 和现有厂商错误码表，先匹配明确业务码，再看 HTTP（超文本传输协议）状态。`ModelFailureInfo.retryable` 是输入信号，重试执行器仍作最终判定。
- 保持 `src/main/orchestrator/vendors/sdk-stream/client-config.ts` 中 SDK（软件开发工具包）内置 `maxRetries: 0`，避免 SDK 和项目同时重试。新增一个轻量的模型请求执行器，用于两条主模型路径；不引入额外通用重试依赖。
- `src/main/orchestrator/harness/retry-policy.ts` 专管工具及其副作用，不能直接拿工具重试决策处理模型请求。等待使用 Node 标准库 `node:timers/promises.setTimeout` 的取消信号；工具的 `sleepWithJitter` 会改变服务端指定的等待时间，不直接复用。
- 继续通过现有 AG-UI（智能体界面事件协议）自定义事件通道发送状态。状态只含枚举类别、序号和等待时长，不含原始错误、请求体、密钥或提示词。

## 策略

| 情况 | 行为 |
| --- | --- |
| 任意模型请求错误（包括鉴权、额度、参数、未知错误），且尚无流式增量 | 在剩余预算内按用户配置次数重试；错误分类只用于诊断，不决定是否重试 |
| 当前模型操作已收到任一文本或推理增量 | 不重发，避免重复输出；未完成的工具调用片段只算连接活动，工具尚未执行 |
| 服务端 `Retry-After` | 支持秒数和 HTTP 日期，按建议时间等待，最多等待 5 分钟；再受本轮剩余预算约束 |
| 用户取消或运行结束 | 立即终止请求或等待，清除重试状态 |

等待采用 2 秒起步、每次翻倍、普通退避上限 60 秒，并在 50%–100% 区间加抖动。服务端明确给出的有效 `Retry-After` 优先于普通退避，不施加 60 秒上限。已有聊天整轮超时仍生效；等待及再次请求不得越过剩余整轮预算。运行设置中的 `modelRequestTimeoutSec`（默认 60 秒）用于流式请求的**连续无协议增量超时**，文本、推理和工具调用片段均重置计时；非流式主模型及摘要请求从发起到完整响应也受同一单次上限约束。取消和无增量超时必须区分，不能把用户取消当成网络故障重试。

明确的“流式协议不支持”沿用一次性非流式降级。降级属于同一尝试，不消耗重试次数；之后若需重试，直接用非流式方式，不重复探测流式能力。聊天模式的图片文字替代仍只在带图片请求返回 HTTP 400 且分类为 `INVALID_REQUEST` 时触发。请求成功后只记账一次，失败尝试不得写入对话轨迹或触发工具执行。

## 界面与事件

运行设置增加数字输入、范围说明和“0 关闭；填写的是额外重试次数”的提示。聊天消息的活动区显示“连接中断，等待 2 秒后重试（1/5）”或“正在重新连接（1/5）”；类别文案按已有错误分类翻译，不显示厂商原始消息。状态事件 `cyrene.model.retry` 包含 `phase`（`waiting`、`attempting`、`cleared`）、`retryNumber`、`maxRetries`、可选 `delayMs` 和可选 `category`。服务端、桥层和前端共用类型。

重试状态属于当前运行的临时界面状态，不写入消息正文、聊天历史、检查点或持久化活动记录。首次有效输出、成功、最终失败、取消、切换/恢复会话时清除；旧运行的迟到事件不能覆盖新运行。超出次数时只显示既有最终错误提示，不留“重试中”假状态。

## 验收

1. 旧配置无字段时显示 5；保存 0/1/10 后重启仍保持，非法值归一到 0–10，切换模型档案不改变全局值。
2. 对零输出的 429 限流、网络中断、超时和 5xx，按设置次数重试；明确欠费或配额耗尽即使返回 429 也只调用一次。
3. 文本或推理已有增量后报错时只调用一次，保留已显示内容和原错误处理；工作模式不能重复执行工具。
4. `Retry-After`、无增量超时、用户取消、总预算到期均有确定行为；取消后无后续请求。
5. 聊天、工作及压缩摘要都使用同一策略；状态显示、更新、清除与实际尝试同步；重试不会重复记账或留下持久化状态。
