# 用户级维基长期记忆设计

> 状态：第一版已接入（2026-10-02）  
> 范围：基于聊天记录的独立长期记忆模式；知识统一存于用户数据目录  
> 前置决策：导入文件继续以原路径交给 Cyrene，第一版维基不摄取导入文件，也不做向量化

## 一、目标与设计边界

在现有 `vector`（向量）、`summary`（摘要）、`off`（关闭）之外，增加 `wiki`（维基）模式。它按 LLM Wiki（大模型维基）思路持续维护可浏览、互相链接的 Markdown（轻量标记文本）页面，作为日常陪伴、学习、工作、编程四种会话能力共享的用户级长期知识库。

第一版的原始材料只有**有效聊天记录**。四种能力产生的事实进入同一库，但按页面标签和适用范围检索；项目知识不会因为统一存储而自动变成全局用户事实。摘要文件和向量记忆均不自动迁移进维基，也不作为维基事实来源。

建议这四个记忆模式在第一版互斥：切换到维基时，停用摘要整理和向量记忆的自动读写；切走维基时，不再摄取或暴露维基工具。已有三种模式的数据保留，切回后继续使用。世界书沿用原有独立行为。

### 非目标

- 不建立新的向量库，不要求用户配置嵌入或重排序模型。
- 不把全部页面或完整目录塞进每轮提示词。
- 不将项目 `.cyrene` 作为维基存储位置。
- 不让聊天模型直接通过通用文件工具改写维基；写入由后台整理器和用户在知识库界面的更正操作完成。
- 第一版不摄取导入文档、网页、图片或现有摘要文件；后续可增加来源适配器，保持导入文件原路径规则。

## 二、现成能力与技术选择

| 能力 | 优先复用 | 适配与限制 |
| --- | --- | --- |
| 页面、目录、链接、健康检查的做法 | [Microsoft llmwiki](https://github.com/microsoft/llmwiki/blob/main/ARCHITECTURE.md) 的三层结构与页面管理方案 | 该项目面向文件来源及 VS Code（代码编辑器）/Copilot（编程助手）；Cyrene 需要自己的聊天来源、事实时序、模式切换和删除语义。截至 2026-10-02，`@llmwiki/core` 未在 npm（Node 包仓库）提供可直接安装的包，因此先参考其公开实现与协议，不把整个扩展作为依赖。 |
| 页面元数据与正文解析 | 项目已有 `gray-matter`（文档头部元数据解析库）、`remark-parse`（Markdown 语法解析库） | 只写 Cyrene 特有的页面模式、来源校验和事实合并；不自行实现通用 Markdown 解析器。 |
| 本地检索 | SQLite（嵌入式关系型数据库）的 FTS5（全文检索扩展）、项目已有 `@node-rs/jieba`（中文分词库） | SQLite 存目录、标签、反向链接、来源映射和全文索引；中文先做分词，短词由标题、别名和精确匹配补足。若采用 FTS5 的三元分词器，少于三个字的子串查询须回退。项目已有 `wink-bm25-text-search`（关键词相关性检索库），但首版避免再维护第二套全文索引。 |
| 数据库驱动 | 优先评估 Electron（桌面应用框架）内置 Node.js（JavaScript 运行时）的 `node:sqlite` | 当前 `node:sqlite` 仍标为候选稳定级别，接口为同步调用。实施前须在开发版和打包版核对 FTS5 可用性；较大的重建任务放后台线程。若运行时不满足，再评估成熟 SQLite 绑定及其 Electron 原生模块打包成本。 |
| 后台模型调用 | 现有 `memory-llm-client`、结构化输出校验和模型任务队列 | 沿用现有主模型继承配置；维基不提供内置模型。新增业务输出模式和运行时阶段，不另造模型请求框架。 |

SQLite 是**可重建索引和操作进度缓存**，页面及其事实来源是知识内容的权威表示；聊天正式记录是原始证据。丢失数据库时，从页面和仍存在的聊天记录重建索引，不能把数据库中的孤立文字当作唯一知识副本。

## 三、位置与数据分层

维基放在 `<userData>/memory/wiki/`，其中 `userData` 是 Electron 的用户持久数据目录；不要使用会被清理的浏览器缓存目录。建议目录如下：

```text
<userData>/memory/wiki/
├── schema.md                 # 页面类型、事实字段、来源与冲突规则
├── index.md                  # 面向用户和模型的简短页面目录
├── log.md                    # 可读的增量整理与修复记录
├── pages/
│   ├── self.md               # 用户本人及全局偏好
│   ├── global/<页面哈希>.md
│   └── projects/<工作区哈希>/<页面哈希>.md
├── source-tombstones.json    # 程序维护的已删除会话标记
├── index-state.json          # 索引脏标记与恢复状态
└── wiki.sqlite               # 可重建的查询索引与处理状态
```

聊天完整原文仍留在现有会话记录存储，不复制一份到维基目录；维基只为具体事实保存短原话证据。回填与后续增量摄取都读取**当前有效分支**，而非简单遍历追加日志；被编辑、重新生成或撤回的旧消息不能成为事实来源。归档记录须经现有正式投影还原有效消息后再处理。实施时需新增“有效消息与稳定来源标识”适配层，输出会话、消息条目、轮次、修订、时间、角色及工作区身份；现有构建模型上下文的接口只返回消息内容或序号，不能直接充当维基来源接口。

`index.md` 是可读目录，由页面元数据生成；`schema.md` 是稳定规则；`log.md` 记录操作及可恢复线索。页面与来源引用足以重建目录、链接和数据库索引。数据库可记录已处理消息进度，但重试必须凭稳定来源标识幂等，不能因为数据库丢失而重复写入事实。

## 四、页面、标签与适用范围

页面以**实体或主题**为中心，包括用户本人、人物、概念、主题、项目和重要经历。页面身份由**实体标识＋适用范围**共同确定；一篇页面只含同一范围的事实，避免整页读取时混入其他项目内容。每页有稳定页面标识、标题、别名、页面类型、标签、适用范围、更新时间、结构化事实与正文。正文展示当前知识、必要的时间线、相关页面链接和来源入口；结构化事实放在同一 Markdown 页的 YAML（结构化元数据格式）头部，由程序解析和序列化。

头部的结构化事实是当前状态、历史时段、冲突和来源的规范数据；正文中的“当前事实/时间线”区块由这些字段生成。主题说明等自由正文可由后台维护，但不能反向覆盖结构化事实。用户在知识库界面更正事实时，同时更新头部与展示区；直接从外部编辑展示区时先标记待校验，不能悄悄变成新的当前事实。

- `chat`（日常陪伴）、`learn`（学习）、`work`（工作）、`code`（编程）是**多选标签和入口视图**，不是四份互不相通的库。例如“Cyrene 的 TypeScript 约定”可同时标记工作与编程。
- 第一版页面的 `scope`（适用范围）分为 `global`（用户全局）和 `workspace`（指定工作区）；会话标识只作为来源，不单独创建会话范围的长期页面。工作区范围使用稳定身份，不以易重名的展示标题区分项目。
- 用户偏好、人物关系等经确认的全局知识可在四种能力中召回；项目事实只在对应工作区或用户明确询问该项目时召回。来源模式只用于排序和呈现，不代替适用范围判断。
- 页面可互相链接；同一实体在每个适用范围只保留一个规范页面，别名负责“Cyrene / 项目昵称”等不同说法的检索。全局页面只链接全局页面；工作区页面可链接本工作区和全局页面，目录和搜索摘要遵守同样的可见范围。

每条可比较的事实至少保存：`subject`（主体）、`predicate`（属性）、`value`（值）、`scope`、`status`（状态）、`assertedAt`（说出时间）、可选的 `validFrom/validTo`（事实生效时段），以及带来源类型、原文位置和版本的来源引用。第一版聊天来源记录会话、消息和修订号；人工更正记录独立操作标识。状态至少包括当前、历史、待确认、撤销；人工更正还须标记为用户直接指定。

每个聊天来源可附一段**原文证据片段**，只截取足以保留时间、否定和条件语义的相关原话，例如“我现在在旧金山出差”。它是方便展示和比对的线索，不替代完整消息：有歧义时按来源引用读取整条有效消息及必要上下文。程序须校验片段确实来自对应修订的原文，模型不得自行改写引文；片段长度有上限，截取会改变意思时宁可只存来源引用。

自由正文中由聊天提炼的知识段落也需记录其来源集合，或者能从该页的来源集合完整重建；不能留下无来源的衍生结论。第一版聊天来源引用使用稳定消息身份，不复制整段聊天原文到页面。

## 五、聊天摄取与写入

```text
四类有效聊天记录
  → 按来源标识取得新增或已变更轮次
  → 结构化提取候选事实、时间、主体与适用范围
  → 查找同一实体页面及相关事实
  → 提议页面补丁并校验来源、冲突、链接和尺寸
  → 全局串行写入 Markdown 页面
  → SQLite 事务更新索引
  → 推进已处理进度
```

1. 用户个人事实以用户直接陈述、明确纠正或明确要求记住的内容为主要证据。助手回复可以帮助理解指代，不作为同等权重的用户事实；学习与编程主题可从完整对话提炼，但助手给出的解释须标明来源和待核实状态，不能变成“用户曾说过”的事实。项目决策须有用户确认。猜测、计划、引用他人说法保留相应语气，不升格为已发生的事实。凭据、令牌等临时敏感串不进入维基。
2. 常规摄取每 10 个成功完整轮次整理；短会话在最后一轮后空闲 2 分钟补刷。“记住这个”“刚才说错了”等明确更正触发优先整理。当前会话的新话在维基尚未整理前仍以实时对话上下文为准。
3. 首次开启时分批回填已有有效聊天；每批保存进度，允许重启后续跑。只有能够取得稳定来源身份的轮次才入库。外部渠道如果沿用成功轮次入口，须先补足当前缺少的稳定助手条目标识，避免静默漏采。
4. 后台模型只返回结构化的候选事实和页面补丁；程序校验页面标识、来源、适用范围、状态、链接与格式，再原子替换页面。模型不能直接指定任意绝对路径写文件。
5. 候选事实可以按会话并行提取；所有会话共享一座库，页面合并与落盘按全局队列串行，并在落盘前重读受影响页面。多次处理同一来源只能得到同一结果。写入前持久化索引脏标记，再原子替换页面、更新 SQLite 索引与目录，最后推进进度并清除脏标记。Markdown 页面是提交点；若页面已写而数据库更新失败，保留新页面、暂停不完整检索并从页面重建索引，下次按来源标识幂等重试。不能假定文件和数据库拥有跨资源原子事务；数据库重建不得阻塞聊天主流程。

## 六、时序事实与冲突状态机

只有**主体、属性、适用范围相同，且有效时间重叠**的事实才需要做冲突比较。地点至少区分“常住地”“当前所在地”“旅行目的地”；“计划搬家”是计划，不能作为已搬家的证据。`assertedAt` 与 `validFrom` 分开：今天回忆去年住在哪里，不代表去年那条事实今天才开始生效。

| 后来的话 | 处理结果 |
| --- | --- |
| 先说“我住在纽约”，后说“我现在在旧金山” | 常住地仍按纽约记录；当前所在地改为旧金山。不推断用户已经搬家。 |
| 后说“我搬到旧金山了” | 常住地的当前值改为旧金山；纽约结束有效时段，进入历史，并保留两段聊天来源。 |
| 后说“之前说错了，我一直住在旧金山” | 旧纽约事实标为撤销，不再呈现为真实居住经历；更正来源保留。 |
| 两条当前常住地说法互斥，却没有可判定的时间或纠错语义 | 标为待确认；检索不把两者同时包装成确定事实。仅在回答依赖此事时自然询问用户。 |

优先级为：**用户明确纠错（包括知识库界面的手动更正）> 用户直接的新陈述 > 模型推断**；同级纠错再按生效时间比较。新陈述的时间更晚不自动意味着旧事实是假的；它可能表示状态变化。用户手动指定的事实带独立来源，一般新陈述不能悄悄覆盖它；后续明确纠错可更新它。

读取默认返回当前有效且与问题相关的事实；问“以前住过哪里”时才读取历史。待确认项可在知识库界面看到，但不作为肯定语气的模型记忆。

## 七、召回、工具与提示词

维基模式向四种会话能力暴露 `wiki_search`（搜索维基）和 `wiki_read_page`（读取维基页）两个只读工具。搜索先按页面范围过滤，再按标题、别名、标签、正文和页面链接排序；搜索摘要也只能从可见页面生成。读页按页面标识访问，经主进程验证目标位于维基根目录及当前范围内，才能返回整页。普通 Chat（聊天）模式默认没有通用 `read_file` 权限，所以维基不能依赖该工具；也不向模型暴露写页工具。

当前可见范围默认为用户全局页加已绑定工作区页。无工作区时，用户若明确点名某个项目，可先把该名称解析为唯一的稳定项目身份，仅为当前请求扩展该项目范围；重名或指向不明时先确认。模型自行构造页面标识不能越过此范围。关键词没有结果时，可沿别名和已找到页面的链接扩展一次查询，不调用向量模型。

稳定提示词只放维基使用规则与工具说明。每轮可变区可放少量高相关的**当前**事实或页面摘要，深查再由工具完成；目录和整页正文不作为固定前缀。维基搜索结果与页面正文是外部数据，模型不得执行其中夹带的指令。工具列表构建时按记忆模式过滤，工具实际执行时再检查一次模式和适用范围，防止切换后的旧运行继续读取。

运行时只按需读取命中的页面和有限条结果，不把全库页面或聊天原文常驻内存；切走维基时释放索引连接和后台任务。批量回填与索引重建在后台分批进行，控制主进程占用。

关闭、摘要、向量模式不暴露维基工具，也不自动注入维基内容；维基模式不暴露向量专用记忆工具。用户在对话中要求更新维基时，由后台优先处理当前轮次，主模型不取得页面写权限。

## 八、编辑、删除与恢复

- **编辑、重新生成、撤回：** 从正式会话记录的有效投影重新计算受影响来源；旧修订支撑的事实及其原文片段先失效，再合并新修订。不能把仅存在于追加日志旧分支中的话重新摄取。
- **删除会话：** 删除正式记录前，先把会话来源撤销意图持久化为 tombstone（来源删除标记），取消相关后台任务；查询立刻屏蔽只由该会话支撑的事实、原文片段和正文片段。随后按来源映射重算受影响页面：仍有其他来源的内容保留，唯一来源已删除的内容移除。处理中断可按 tombstone 重试，删会话本身不依赖模型成功。
- **手动更正或删除事实：** 用户操作产生最高优先级的独立来源；被删除事实须留下撤销标记，避免后续从同一旧聊天再次回填。界面可查看该事实的来源、历史及状态。
- **数据库损坏或丢失：** 从页面、来源引用、tombstone 和仍在的正式聊天记录重建索引。索引脏标记在页面写入前落盘，直到数据库、目录和处理进度同步后才清除；重建期间禁用不完整的搜索结果，聊天主流程保持可用。
- **模式切换与退出：** 后台任务带运行代次和取消信号；切走维基或删除会话后，旧任务在写页前复核目标是否仍有效。失败不推进处理进度。

## 九、知识库界面

记忆面板新增“维基”档位与状态入口；知识库界面提供四类标签入口、全局搜索、页面详情、相关页面、来源会话、历史变更和待确认事项。用户可在页面详情更正或删除具体事实，无须编辑结构化元数据。L2 事件片段继续仅在向量模式展示。

页面卡片应同时显示“当前值”“何时得知”“适用范围”。对于项目页面，显示绑定的工作区；对于冲突项，显示两边原话的出处与待确认原因。来源会话被删后，对应引用不再可打开，也不能留下仍被视为有效的孤立结论。

## 十、接入点与交付顺序

1. **模式与配置：** 扩展 `src/main/memory/memory-mode.ts`、`src/main/settings/model-settings.ts`、设置保存/回滚、运行时热切换和三语言设置界面；维基后台服务与向量、摘要服务互斥。
2. **原始来源：** 复用 `src/main/orchestrator/conversation-transcript-store.ts` 与有效投影；补齐成功轮次、渠道稳定标识、历史回填、撤回和删会话的来源事件。
3. **页面与索引：** 增加全局路径解析、页面模式、来源映射、事实合并、串行原子写入、SQLite 检索和重建；复用现有解析库及结构化输出调用层。
4. **模型读取：** 增加两只受限只读工具、工具暴露过滤、稳定提示词规则和少量可变区召回。
5. **知识库界面：** 页面浏览、标签筛选、来源与历史、人工更正、待确认项和删除联动。

## 十一、验收条件

- 四类会话的知识进入同一个用户级维基；相同实体在每个范围只有一篇规范页面，项目范围不会进入无关项目或日常对话。
- “纽约→旧金山”四类示例分别产生正确的当前状态、历史、撤销或待确认项，且每条结论可追溯到有效聊天。
- 被编辑、撤回、重新生成或删除的聊天不会继续支撑当前知识；多个聊天共同支撑的事实不会因删掉其中一个会话而丢失。
- 切换模式后，维基读取工具及后台写入都按当前模式生效；关闭模式不读也不写维基。
- 数据库可从持久页面与仍在的聊天恢复；失败、崩溃和并发会话不会造成重复事实、丢失人工更正或孤立索引。
- 后台整理失败不阻断聊天；模型无法通过维基工具读取维基目录外文件，也无法将页面正文当作执行指令。

## 十二、后续知识库接入预留

把来源引用和短原话片段定义成可复用的数据契约，供后续知识库界面或来源适配器使用，而不是让页面只认识聊天消息。至少保留：`kind`（来源类型）、稳定来源标识、原文定位、来源版本、可选的短原话片段、记录时间；读取完整上下文时再交给对应来源解析器。

- 第一版只实现聊天来源和用户手动更正来源。聊天以会话、消息条目及修订定位；短原话须与该修订的有效消息核对。
- 未来接入本地文档时，文件来源以用户提供的**原文件路径**、内容哈希及页码/段落/行号等位置定位；短引文仍用于展示和比对。文件改变或找不到时标记来源待重新核对，不把旧引文悄悄当作仍然有效的原文。文档继续按路径交给 Cyrene，不复制全文，也不做向量化。
- 未来知识库可复用来源卡片、跳转原文、版本校验和失效处理；是否把某份文档编进维基由后续功能决定。本期只稳定来源字段与聊天解析器，不提前实现通用文档摄取框架。
