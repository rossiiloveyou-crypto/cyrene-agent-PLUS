# Cyrene 右侧浏览器控制方案

> 设计日期：2026-10-01。实现基线是浏览器隔离工作区的 `bc587073`；用户已确认方案并要求开始实施。代码已落入本隔离工作区，尚未运行构建或测试。

## 目标与范围

Cyrene 能在同一次任务中打开右侧浏览器、进入指定网站、读取可操作元素、执行点击／输入／按键／滚动，并在需要判断视觉效果时截取右侧网页。用户能在右侧看到它正在操作的标签页；Cyrene 也能交替修改项目代码和验证页面。

控制的是右侧浏览器当前绑定的网页视图。截图范围是这个网页的当前视口及滚动位置，不包含桌面、Cyrene 主界面、浏览器标签栏和地址栏。首版不建立另一个隐藏浏览器。

现有 `browser_get_page_elements` 和 `browser_get_element_css` 继续提供只读检查；进入控制模式后增加交互与截图工具。退出控制模式只解除控制权，不关闭网页或清除登录状态。

## 现状与复用决定

| 已有能力或现成接口 | 复用方式 | 还需补齐 |
| --- | --- | --- |
| [BrowserPanelController](../../src/main/browser/browser-panel-controller.ts) 的多标签 `WebContentsView`、HTTP(S) 导航及持久化会话 | 直接操作同一网页视图和 Cookie 分区；不启动第二套浏览器 | 按对话绑定标签页和控制权，并自动打开右侧面板 |
| [Playwright 页面快照](../../src/main/browser/playwright-page-snapshot.ts) 的原始语义树、`observationId`、`ref` 映射 | 延续现有元素识别和用户手选元素的编号，不另造 HTML 清理器 | 操作前重新确认节点、可见性、命中位置和编号有效性 |
| 已安装的 `@playwright/mcp` | 保留作能力参考，不作为右侧浏览器控制入口 | 单独接 MCP 不会自动绑定当前 Electron 标签；仍需连接与标签映射，还增加一层工具传输 |
| Electron 的 `webContents` 输入及 `capturePage` 接口 | 对既有网页视图输入和截图；截图直接取网页视口 | 输入事件在当前窗口、焦点与复杂网页上的行为需先做针对性验证；图片还要送进模型视觉链路 |
| [图片路由](../../src/main/orchestrator/image-router.ts) 和 [视觉转述器](../../src/main/orchestrator/vision-captioner.ts) | 纯文本主模型使用已配置的视觉模型转述截图 | 多模态主模型直接接收截图，需要扩展目前仅支持字符串的工具结果 |
| [工具注册与权限](../../src/main/orchestrator/tools/registry/tool-registry.ts) | 沿用现有工具定义、Work／Code 模式、`input-control` 权限与工具执行记录 | 一次运行内工具清单目前固定，真正的按控制状态暴露需要改 Harness |

Playwright 官方的 `connectOverCDP` 可以接入现有 Chromium，但其官方文档说明该连接的能力低于 Playwright 原生连接，且非 Playwright 启动的浏览器可能有兼容差异。首版优先复用当前快照与 Electron 的输入接口，只写将 `ref` 映射到既有网页视图的适配代码。当前快照依赖 Playwright 包内的非公开注入脚本，后续升级依赖必须验证兼容性。Electron 的 `sendInputEvent` 要求宿主窗口有焦点；首版遇到失焦应明确暂停操作，不主动抢用户焦点。若输入验证发现不可接受的兼容问题，再单独评估 CDP 输入，不同时维护两套选择器与浏览器实例。

## 控制会话与标签页规则

1. `browser_control_start` 打开并激活右侧浏览器面板，等待网页视图拿到有效尺寸，然后绑定 `conversationId + tabId`。默认绑定用户当前选中的网页标签；空标签也可进入，随后由 Cyrene 打开网址。`runId` 用于调用上下文和审计，不决定控制会话的生命周期。
2. 同一浏览器控制器同时只允许一个对话持有控制权。这个对话可以跨多轮运行继续控制；其他对话和子代理不能借用该控制会话。普通读代码、写代码和终端工具仍可用。
3. 所有交互和截图作用于绑定的 `tabId`，不随用户手动切换标签而悄悄转移。用户切换标签或收起右侧浏览器后，下一次操作返回可恢复的“目标未显示”错误；Cyrene 须重新选择目标或等面板恢复。
4. `browser_open_url` 默认在绑定标签页导航；显式要求新标签时，创建、显示并原子地绑定新标签。网页自身打开新标签时，工具结果报告新 `tabId`，Cyrene 可显式切换过去。
5. 只有 `browser_control_stop`、绑定标签关闭或窗口销毁会释放控制权。Cyrene 一轮回复结束或任务取消不会自动释放；网页与已有登录状态保留。显式停止后，重新开始控制须建立新控制会话。

## 工具协议

工具执行器从现有 `ToolContext` 取得 `conversationId` 和 `runId`，模型无需在每次调用中重复传控制令牌。每次操作前都校验持有者、标签页和页面状态。

| 工具 | 可用阶段 | 输入要点 | 返回要点 |
| --- | --- | --- | --- |
| `browser_control_start` | 普通阶段 | 可选 `tabId`，省略时绑定当前标签 | 绑定标签、网址、标题、面板是否就绪 |
| `browser_get_page_elements`（已有，需适配） | 普通阶段及控制阶段 | 无；普通阶段读用户当前标签，控制阶段读绑定且当前显示的标签 | 原始语义树、`observationId`、`ref` |
| `browser_get_element_css`（已有，需适配） | 普通阶段及控制阶段 | `observationId`、`ref` | 元素样式；控制阶段校验绑定标签，旧编号拒绝 |
| `browser_open_url` | 控制阶段 | 完整 HTTP(S) `url`，可选 `newTab` | `web`（最终网址）、`tabId`、标题、加载状态 |
| `browser_list_tabs`、`browser_select_tab` | 控制阶段 | 选择时传明确 `tabId` | 可见标签列表；切换后新的绑定标签 |
| `browser_click` | 控制阶段 | `observationId`、`ref` | 执行结果、网址变化或新标签信息 |
| `browser_fill` | 控制阶段 | `observationId`、`ref`、`value` | 输入结果；首版拒绝代理填写密码、验证码及支付字段，交由用户手动处理 |
| `browser_press` | 控制阶段 | 键名，可选目标 `ref` 与 `observationId` | 按键结果；支持 Enter、Escape、Tab 等明确键名 |
| `browser_scroll` | 控制阶段 | 方向、有限的滚动量；指定容器时同时传 `observationId` 和 `ref` | 滚动后的视口位置 |
| `browser_screenshot` | 控制阶段 | 可选视觉问题 `question` | 同一网页视口的图片观察及网址、标签、尺寸 |
| `browser_control_stop` | 控制阶段 | 无 | 控制权已释放 |

`browser_open_url({"url":"https://example.com"})` 完成后返回类似 `{"web":"https://example.com/","tabId":"…","title":"Example Domain","status":"loaded"}`。已知网址直接打开；未知网址先使用项目已有的网页搜索能力，搜索无法取得内容时再用浏览器进入网站、交互和截图。不另建通用搜索引擎。

所有网页文字、属性和截图中的文字都是页面数据，不能作为 Cyrene 的新指令。模型只选择 `ref`；实际节点映射、坐标和样式细节由主进程保管。

## 观察、操作、复查的时序

```text
开始控制 → 右侧面板显示并绑定标签 → 打开网址或读取当前页
         → 获取 observationId/ref → 操作一个目标
         → 检查操作结果 → 重新读取页面 → 继续或退出控制
```

每个标签只保留最新观察。导航、重新观察、标签切换和关闭必须使旧编号失效；现有 `activateTab` 尚未在切换时清除观察，实施时须补上。普通单页应用更新虽未必触发导航，执行器仍须在动作前确认节点仍连接在当前文档、角色／名称与快照相符、可见且未被其他元素遮挡。无法确认就拒绝并要求重新观察，绝不把旧 `ref` 猜成新页面上的另一个元素。

动作按顺序执行。输入接口只在网页视图就绪时使用，不固定睡眠；每个动作有超时，返回“已执行／未执行／结果不确定”的明确状态。动作后不自动把整份网页树塞进结果，Cyrene 再调用页面读取工具观察变化。网页较长时先滚动再观察；跨域 iframe 和 Canvas 的可读性沿用当前快照限制，必要时用截图补充。

写网页时仍按“修改代码 → 等页面更新 → 读取或截图 → 点击验证 → 再修改”的顺序工作。浏览器控制模式只增加浏览器能力，不移除文件与终端工具。

## 截图与模型视觉输入

控制器对绑定标签的 `webContents.capturePage()` 截当前网页视口。截图前确认标签仍显示、视图尺寸有效、加载状态可用，并限制像素与字节数。截图来自网页本身；按钮栏、其他窗口和桌面不进入图片。动画页面按捕获瞬间呈现；用户滚动后再调用即得到新的视口。

当前 [ToolDefinition.execute](../../src/main/orchestrator/tools/registry/tool-registry.ts) 和 [工具执行结果](../../src/main/orchestrator/types.ts) 都只支持字符串，所以把 PNG 路径或 base64 文本返回给模型并不等于让它看到了图。目标实现有两条明确路径：

- 主模型支持图像：扩展工具结果为“简短文字 + 图片附件”，在工具轮、持久化、上下文计算及各模型协议适配中传递真正的图片内容。图片字节不进入普通文本日志或工具结果截断器。
- 首轮实现：截图统一走现有视觉转述器。图片字节只作为视觉请求的图片输入，不进入普通工具文本或日志；多模态兼容配置复用主模型端点，文本模型使用已配置的视觉模型。Cyrene 收到明确标注的视觉转述，没有可用视觉模型时明确报错。

即使配置表标记某模型支持视觉，也要以实际使用的协议和端到端图片工具结果验证为准。用户界面可以展示原始截图；模型看到原图还是转述，工具结果须明确标识。首版不提供后台隐藏截图。

## 工具暴露与权限的实现差距

目标行为是：普通阶段提供 `browser_control_start` 和已有只读工具；进入控制阶段后，在下一轮模型调用才提供交互、截图和停止工具；退出后收回。权限配置与当前会话模式仍是上界，开始控制不能绕过用户已关闭的工具。

目前 [Harness 运行状态](../../src/main/orchestrator/harness/cyrene-harness.ts) 明确规定一次运行中的工具清单固定，[运行准备](../../src/main/orchestrator/build-options.ts) 把工具目录写入稳定提示词前缀。只在运行时注册新工具或修改 `enabled`，不会让当前任务的下一轮模型调用看到它们。因此需要独立改造：

1. 运行开始时计算“本任务被允许使用的工具”上界；每轮模型调用前再按浏览器控制状态生成当前可见子集。
2. 模型工具声明、工具目录提示和执行器允许列表必须同时更新；停止后的旧工具调用一律拒绝。浏览器工具目录放在可变层，并在切换时更新缓存世代，保持其他稳定前缀不变。
3. 恢复／中断时没有有效控制会话就回到普通工具集。子代理默认无权继承父任务的浏览器控制权。

若先用“工具始终可见、执行时检查模式”验证浏览器动作，它只能算内部过渡实现，不能对用户宣称已经做到“进入后才暴露”。该过渡也必须校验任务、标签和观察编号。

导航、点击、输入、按键和滚动都声明 `effectKind: "mutation"`，由现有调度器串行执行，并在只读计划中禁止导航与交互。点击、输入、按键和滚动复用现有 `input-control` 风险等级；导航还受网络权限约束；截图按图片路由处理。现有权限档位下，`full` 放行 `input-control`、`per-action` 逐次询问、只读和 `scoped` 档位拒绝；进入控制模式不能绕过此策略。若以后希望 `scoped` 档位也能控制网页，再设计独立的浏览器授权，不把文件权限暗改为全访问。

控制工具支持 Work、Code 和 Learn 模式，Chat 模式沿用现有不提供工具的规则。`browser_fill` 执行前根据目标节点的 `type`、`autocomplete` 等属性识别密码、一次性验证码和支付字段；首版交给用户手动填写。普通输入值仍可能进入现有工具调用轨迹与持久化记录，不能把“工具结果不回显”误认为“完全不记录”。控制器是最终执行门禁，Skill 只能教 Cyrene 按步骤操作，不能代替权限校验。

## 界面与 Skill

主进程需要向聊天页面发“打开并激活右侧浏览器”的请求，并等待页面回报有效尺寸，避免 Cyrene 自主打开网址后仍因面板隐藏而无法观察。控制期间显示绑定标签及当前动作；目标元素可在网页内部短暂高亮。网页截图前移除这类辅助标记，保证截图反映实际网页。用户仍可手动切换或关闭标签，这会使下一步操作暂停并报告原因。

首轮代码通过浏览器面板状态显示控制标签和最近动作；目前没有注入网页内的目标高亮。

新增浏览器操作 Skill，讲清：何时先搜索、何时打开网站；先观察再操作；每次页面变化后重新观察；何时截图（元素信息不足、验证视觉效果或网页功能）；如何在写代码与网页验证间切换；何时退出控制。Skill 不包含隐藏的执行权限。

## 实施顺序与验收

1. **验证基础输入和图片链路。** 在现有 `WebContentsView` 上确认输入、滚动、焦点、截图尺寸与当前视口一致；验证视觉转述链路。代码已按 Electron API 接入，但运行行为尚未验证。
2. **建立控制会话和界面桥。** 打开右侧面板、绑定标签和任务，处理用户切换、关闭、并发任务、取消及释放。
3. **实现 URL 与元素操作。** 沿用当前导航和 Playwright `ref`；让已有元素与 CSS 读取工具在控制阶段使用绑定标签，并在切换标签时清除旧观察；补齐动作前验证、串行执行、明确错误、操作后的重新观察。增加显式多标签选择。
4. **接入截图。** 同一绑定网页视口截图、图片结果路由、视觉转述降级及用户可见状态。
5. **实现按轮动态工具暴露，补 Skill 和动作展示。** 同步更新 Harness 工具目录、执行允许列表和缓存状态，避免只在界面上显示模式但模型仍拿着旧工具清单。

验收至少覆盖：用户给网址后 Cyrene 自行打开并读到网页；普通搜索失效后进入动态网站；代码修改后在同一任务内验证页面；多标签切换不会控制错页；旧 `observationId/ref` 被拒绝；右侧隐藏时无暗中操作；截图只含当前网页视口且主模型确实收到图像或明确的视觉转述；退出后交互工具消失、网页与登录状态保留。
