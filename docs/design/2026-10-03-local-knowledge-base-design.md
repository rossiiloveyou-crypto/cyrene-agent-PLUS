# 本地知识库设计方案

> 状态：首版已接入；文档来源晋升维基与更多格式留待后续
> 范围：用户主动管理的本地资料；在设置页新增独立的“知识库”标签
> 前置约束：文件以原路径交给 Cyrene，不复制原文，不切固定长度片段，不生成向量

首版已加入独立设置页和知识库总开关。关闭后保留资料集目录与索引，停止扫描，并从模型可用工具列表撤下知识库检索和读取工具。当前支持文本文件与文件夹登记、全局或工作区范围、后台索引、按原路径检索和受限读取。文件夹预览、自定义包含规则、单文件重试以及文档来源晋升维基仍属于后续工作。

## 一、定位与边界

设置页中的“记忆”和“知识库”分别承担以下职责：

| 区域 | 权威来源 | 主要用途 | 写入方式 |
| --- | --- | --- | --- |
| 记忆标签中的维基记忆 | 有效聊天记录、用户手动更正；未来可引用文件 | 保存持续更新的人物、偏好、经历和项目事实 | 现有维基整理器与用户更正 |
| 知识库标签中的本地资料 | 用户选定的原文件 | 查阅手册、笔记、规范、学习资料等 | 用户添加或移除路径；应用只维护目录与检索索引 |

资料库是独立能力，不作为第五个记忆档位。用户关闭或切换记忆模式时，已启用资料集仍可供当前会话检索；维基记忆是否进入模型上下文仍由维基档位控制。资料库内容不自动写成“用户事实”，也不自动写入维基。用户明确要求记住一条结论或在界面选择加入维基时，才走带出处和版本的维基事实流程。

首版只处理本地文本文件。用户临时附加到某一轮的文件沿用现有附件流程，不自动加入长期资料库。后续的网页、云端文件和二进制文档各自通过来源适配器接入，不改变本地文件的原路径原则。

## 二、复用现成能力

| 需求 | 采用的现有方案 | 可替代的自建部分 | 成本与限制 |
| --- | --- | --- | --- |
| 全文检索 | 已在维基使用的 SQLite（嵌入式数据库）FTS5（全文检索扩展）与 `@node-rs/jieba`（中文分词库） | 不另建关键词搜索引擎，也不引入向量数据库 | 索引会在磁盘留下词项；没有语义近似匹配，别名和改写查询只作补充。索引丢失可从原文件重建。 |
| 数据库访问 | 已在维基使用的 `node:sqlite`（Node.js 内置数据库接口） | 不增加另一种数据库绑定及桌面打包工作 | 当前接口同步执行；批量建索引要放后台工作线程或受限批次，不能长时间阻塞主进程。 |
| 文本读取 | `src/main/orchestrator/tools/fs-tools.ts` 中的 `read_file`（文本文件读取工具）和 `src/main/orchestrator/tools/search-text-tools.ts` 中的 `search_text`（文件文本搜索工具） | 复用绝对路径、行号、大小上限和错误语义 | 当前 `read_file` 只支持文本，且聊天里的工具暴露受附件条件约束；资料库需抽取共用的安全读取函数，并另设按登记来源授权的只读入口。 |
| 文件变化检测 | 标准库的文件状态、内容校验值；项目已有 `chokidar`（文件变化监听库）可留作后续实时同步 | 首版无需常驻扫描全部资料目录 | 启动时只加载目录；空闲时分批检查，命中时复核。实时监听以后按需增加，避免大目录监听长期占资源。 |
| 知识出处 | 现有维基的 `WikiDocumentSource`（文档来源引用）预留字段 | 不重新设计“文件路径＋版本＋位置”的来源契约 | 目前仅有类型和界面映射；真正加入维基前，还须补文件来源的反向映射、版本失效和删除联动。 |

上述依赖已在项目中使用。资料库只实现资料集、来源授权、检索位置和生命周期这些业务逻辑。完整文档解析器不属于首版；增加格式时优先评估成熟解析库，不拿现有生成文档的依赖冒充读取器。

## 三、资料集与数据位置

资料集是用户显式建立的一组文件或一个文件夹。每个资料集至少有：稳定标识、名称、适用范围、启用状态、路径列表、创建时间和最近扫描状态。

- 适用范围为用户全局或指定工作区。添加时若会话已绑定工作区，默认使用该工作区；选择全局需要在界面明确操作。工作区以稳定身份匹配，不依赖展示名称。
- 文件可属于多个资料集，但原文件只保留在用户指定路径。每条来源记录保留规范化绝对路径、展示名称、大小、修改时间、内容校验值、格式和索引状态。
- 稳定来源标识由资料集标识和登记时的规范化路径生成；文件改名或迁移先使旧来源失效，再由用户重新登记或确认迁移，避免把不同文件误认作同一来源。
- 文件夹可设置包含规则与排除规则。默认排除隐藏目录、构建产物、依赖目录、二进制和超出大小上限的文件；界面展示跳过原因。
- 删除资料集只删除 Cyrene 的目录记录与检索索引，不删除原文件。文件移动或消失后显示“来源不可用”，不把旧命中继续交给模型。

持久位置建议为 `<userData>/knowledge/`：

```text
<userData>/knowledge/
├── collections.json   # 用户选择的资料集、路径、范围与启用状态；权威目录
└── search.sqlite      # 可删除重建的文件元数据与全文索引
```

`collections.json` 原子写入。数据库只是派生索引，损坏后根据目录和仍存在的原文件重建。索引可包含搜索词项及位置标识，因此它仍是用户本地资料数据，删除资料集时要同步删除对应索引；“不复制原文”并不等于“索引不占磁盘”。

## 四、文件登记与检索流程

```text
用户选择文件或文件夹
  → 校验路径与适用范围，保存资料集目录
  → 空闲时按文件逐个读取并建立关键词索引
  → 搜索返回资料集、原路径、命中位置与当前版本
  → 读取工具重新校验路径和版本，从原文件取所需范围
  → 模型回答时引用文件与行号，或明确说明来源已失效
```

### 索引

1. 首版支持纯文本、Markdown（轻量标记文本）、常见代码与配置文件。单文件上限先与现有文本工具一致，设为 10 MB；超限、不可读和疑似二进制文件明确标记，不静默截断。读取前先检查文件状态，避免现有 `read_file` 先把超大文件整体读入内存的行为。
2. 按文件及自然结构（例如 Markdown 标题）记录检索位置，不建立固定长度片段，也不存完整正文副本。FTS5 采用不保存正文列的索引形式；具体表模式须在应用内置的 SQLite 版本上核对更新与删除能力。展示命中上下文时重新读取原文件。
3. 中文沿用现有分词。排序优先考虑标题、路径名、完全词项、正文命中与资料集范围。检索失败时允许一次关键词改写或别名扩展；仍无结果就如实返回空结果。
4. 索引任务在后台逐文件执行，限制并发、单次读取量和每批耗时。启动时不全量读文件；空闲时检查文件状态，状态变化再计算校验值。搜索命中与正式读取前再次验证文件版本。需要及时更新时，用户可手动刷新资料集。

### 模型工具

- `knowledge_search`（搜索资料库）：只查当前会话已启用且范围可见的资料集，返回少量文件名、原路径、命中位置、摘要和版本标识；不输出整份文件。
- `knowledge_read`（读取资料来源）：接受搜索返回的来源标识和位置，由主进程解析登记路径、检查当前范围及文件版本，再读取有限行数。模型不能借这个工具传任意绝对路径。
- 读取前复核规范化路径及符号链接最终指向，确认它仍是登记的文件；检查和打开之间发生替换时须拒绝或重新校验，不能凭搜索结果中的路径直接开放文件系统访问。
- 工具在构建模型可见列表时按资料集启用状态过滤，执行时再复核一次；切换工作区或关闭资料集后，旧调用也不得继续读取。
- 文件正文始终作为资料处理，不执行其中的指令。引用必须指向实际读过、且版本仍有效的原文件位置。

现有聊天模式的 `read_file` 暴露依赖附件条件，不能直接拿它作为资料库工具的权限边界。可以复用其底层文本读取与行号格式，但资料库读取必须通过登记来源标识和范围校验。

## 五、与维基记忆的连接

资料库搜索结果不会自动变成维基事实。若用户明确要把文件中的信息记入维基，流程为：

1. 从原路径读取具体位置，形成候选事实和短原文证据；验证短引文确实来自当前文件版本。
2. 记录 `kind=document`（文档来源）、稳定来源标识、原文件路径、内容校验值、行号或标题位置、记录时间。
3. 按维基已有的主体、属性、适用范围和时间规则合并。文档陈述与用户直接更正发生冲突时保留来源和待确认状态，不让文件内容覆盖用户明确指定的个人事实。
4. 文件修改、移动或移出资料集时，通过来源反向映射找到依赖的维基事实，标记待核对或撤销失效来源；有其他有效来源支撑的事实继续保留。未重新核对前，模型不能把失效引文当作现行证据。

当前维基只对聊天来源建立反向索引；上述第 4 步需要扩展现有来源映射和恢复流程。资料库首版可以先提供“查阅并引用”，待来源失效链路完成后再开放“加入维基”。

## 六、设置页界面

在设置页左侧导航的“记忆”正下方增加同级标签 **“知识库”**。这是一整页独立设置，不是“记忆”页内的二级切换；即使记忆档位设为“关闭”，标签和已登记资料也照常显示。现有“记忆”页保留模式切换、摘要、向量和维基事实浏览；文件资料的添加、索引、搜索与管理集中在新的“知识库”页。

“知识库”页建议采用以下布局和操作：

1. **页头：** 标题、简短说明、搜索框和“添加资料集”按钮。说明中写明文件仍在原位置，删除资料集不会删除原文件。
2. **资料集列表：** 每张卡显示名称、全局或工作区范围、启用状态、文件数量、最近扫描时间、索引进度和错误数量。可以暂停、刷新、查看、删除。
3. **资料集详情：** 展示已登记的原路径、格式与状态；可添加单个文件或文件夹、移除路径、查看跳过或失败原因。添加文件夹时先预览将纳入的文件数量和排除规则，确认后后台扫描。
4. **搜索结果：** 支持按资料集筛选，显示文件名、命中位置、少量原文上下文、文件版本和“打开原文件”。文件不存在、版本改变或无权限时显示状态并禁用旧位置引用。
5. **空白与异常状态：** 首次进入引导用户添加资料；索引进行中仍可看已完成文件；失败文件可单独重试，不让一个坏文件拖住整库。

导航接入点为 `AppearanceSettingsPage.tsx` 的设置分区与侧栏；新增独立的知识库设置面板，并补齐三种语言的标签和状态文案。现有 `MemorySettingsPanel.tsx` 中的维基页面浏览继续留在“记忆”标签。模型在回答中引用资料时显示资料集、文件名和位置；文档来源未来加入维基后，维基事实详情可以跳到原文件位置。

## 七、交付顺序

1. **目录与界面：** 在设置页“记忆”下方增加同级“知识库”标签；建立资料集和路径登记，先支持单个文本文件，界面能查看路径、范围与状态。
2. **检索与读取：** 复用现有数据库和分词能力，接入后台增量索引、两个受限只读工具、原路径读取及来源引用。
3. **文件夹与恢复：** 增加文件夹规则、分批刷新、文件变化与丢失处理、索引重建、资源限额。
4. **维基晋升：** 完成文档来源反向映射与失效联动，再提供明确的“加入维基”操作。
5. **更多格式：** 在各格式的可靠读取和位置定位就绪后，逐一接入；首版不承诺扫描件识别、网页或云端同步。

## 八、验收条件

- 加入资料库的文件在原位置保持不变；删除资料集不删除文件，索引删除后可重建。
- 全局与工作区范围正确隔离；模型不能通过资料库工具读取未登记的任意路径。
- 文本资料能被中文关键词检索；回答可回到实际原文件和行号，且不会把未读取的命中描述成已核实原文。
- 文件修改、移动、删除或无权限时，旧索引和旧引文不会被当作当前有效资料。
- 批量索引受文件大小、并发和后台批次限制，聊天主流程不因同步数据库调用长期卡住。
- 资料库在各记忆档位下按启用范围工作；未明确加入维基的资料不生成个人记忆事实。
- 设置页左侧“记忆”下方有独立“知识库”标签；关闭记忆后仍可管理和使用已启用资料集，维基事实浏览保留在“记忆”页。
