# Learn 交互式试卷设计规格

## 目标

让 Cyrene 按现有 Learn 考试流程生成正式试卷，并在应用右侧提供逐题作答页面。出卷与批改分属两个独立轮次：出卷轮结束后，用户可以稍后作答；只有用户主动交卷时，应用才把试卷、评分资料和答案提交给 Cyrene 批改。

## 已确认的用户体验

- 试卷是一份完整的长试卷，可以混合选择、判断、填空、简答和解答等题型，不是 `pop_quiz` 式的少量抽查卡片。
- 页面采用已确认的预览样式：右侧检查器中的应用内“试卷”页签；左侧为竖向、按题型分组的题目导航；主区域一次显示一道题。
- 导航显示已答、未答和待检查状态；支持上一题、下一题、题目跳转和交卷前检查。
- 试卷页面适配应用浅色/暗色主题。不得用浮层导航覆盖试卷正文。
- 用户输入在本地自动保存。退出应用后重新打开同一对话，能够继续填写已保存的作答。

## 交互生命周期

1. Cyrene 按现有考试技能文档完成知识点规划、题型安排和必要的范围确认。
2. Cyrene 调用正式试卷创建工具，传入版本化试卷数据。主进程校验并保存试卷，生成 `examId`，并打开右侧试卷页。
3. 创建工具立即返回试卷已创建的结果，Cyrene 本轮正常结束。工具不等待用户作答，不保留挂起的模型请求。
4. 用户在本地页面作答。每次答案变更都按 `examId` 和 `questionId` 保存；作答内容不随自动保存发送给模型。
5. 用户点击交卷并确认后，应用先将答案快照持久化并将试卷状态改为已交卷，再启动同一对话中的新一轮 Cyrene 批改。
6. 批改请求必须携带权威试卷、答案/评分标准和交卷快照。Cyrene 根据标准答案与评分细则批改，输出成绩、逐题反馈、能力分析及考试复盘。
7. 若批改请求失败，保留已交卷快照，允许对同一快照重试；不得要求用户重新作答，也不得重复创建一份试卷。

## 数据与信任边界

试卷以版本化 JSON（结构化数据格式）作为规范数据，由 Ajv（JSON Schema 校验库）按题型校验。每题有稳定 ID、题型、题干、分值和题型专属字段；选择题有稳定选项 ID。题型使用可扩展的判别联合，包括单选、多选、判断、填空、简答和解答。答案值按题型保存为选项 ID、选项 ID 列表、布尔值或文本/文本列表。

试卷数据分为两种投影：

- **作答视图**：题干、选项、分值、必要的作答说明。只发送到右侧 React（前端界面库）页面，排除标准答案、参考答案、评分细则和解析。
- **批改资料**：完整题目、标准答案、参考答案、评分细则和解析。保存在主进程管理的试卷记录中，仅在明确交卷后进入 Cyrene 批改请求。

模型生成的题干和文本视为不可信网页内容处理；页面只把它们作为文本/受限富文本渲染，不执行模型提供的 HTML（超文本标记语言）、脚本或事件属性。不得把批改资料放入渲染进程页面状态、DOM（文档对象模型）、调试快照或面向用户的工具输出。

答案自动保存只写入应用本地持久化存储，不触发工具调用或模型请求。交卷操作有确认步骤；确认后形成不可变的答案快照。空题允许提交，但交卷确认需列出未答题目。

## 页面行为

- 复用现有右侧检查器页签和已确认的试卷预览视觉设计，不嵌入外部网站 WebContentsView（网页内容视图）。
- 题目导航按题型分组，支持展开/收起；选中题目显示在主区域。
- 不同题型由受控表单组件渲染；用户可返回修改，导航切题不自动提交。
- 自动保存状态明确可见；离开页面或应用重启后，根据同一试卷记录恢复答案和当前题目。
- 交卷后试卷转为只读并展示“批改中/批改失败/已完成”等状态；批改失败时提供重试入口。
- 交卷后显示 Cyrene 的批改结果；原试卷、答案和结果关联到同一个 `examId`。

## Skill 与产物

- 保留 `cyrene-exam-paper` 当前的考点规划、科目参考资料、确认步骤、评分规划和考试复盘要求。
- 正式试卷通过新建的长试卷工具进入右侧页面；不修改 `pop_quiz` 的用途和题量限制，也不改变日常练习的 `exercises/` 流程。
- 试卷 JSON 是可恢复和重试批改的规范产物。考试复盘继续沿用现有 Markdown（轻量标记文本）输出；试卷/答案 Markdown 导出不属于首版要求。

## 方案选择

采用应用内受控 React 页面 + 版本化试卷 JSON + 主进程持久化会话。项目已使用 React、Radix/shadcn 风格组件与 Ajv；优先复用这些依赖和现有右侧检查器、`pop_quiz` 的类型分层/IPC 模式，不新增通用考试引擎或表单库。`pop_quiz` 仅借鉴信任边界与类型组织，不复用其卡片 UI 或“等待当前模型轮次”的生命周期。

## 失败与恢复

- 试卷数据不符合 JSON Schema：拒绝创建，向 Cyrene 返回可定位的校验错误，不打开半成品试卷。
- 本地答案保存失败：显示保存失败状态，禁止误报已保存；交卷前再次持久化并验证完整快照。
- 用户关闭侧栏或应用：不删除草稿；重开对话后恢复未交卷试卷。
- 重复交卷：同一 `examId` 已交卷时，不创建不同答案快照或重复启动批改；如批改未完成，提供重试。
- 批改触发后模型失败或用户取消：保留状态和答案快照，可从该试卷重新发起批改。
- 新试卷不得覆盖既有试卷记录或答案。

## 明确不做

- 不让 Cyrene 控制浏览器或执行网页操作。
- 不把原始 HTML/JavaScript 作为模型生成页面交给浏览器执行。
- 不让模型在用户作答过程中读取答案变化。
- 不将完整考试压缩为 `pop_quiz` 小卡片，不使用 SurveyJS 等新的考试/问卷库。
- 首版不要求 Markdown 试卷或答案解析导出；只保留现有考试复盘 Markdown。

## 验收标准

1. Cyrene 创建试卷后，该轮结束，右侧试卷仍可作答；没有等待交卷的挂起模型工具调用。
2. 用户填写若干题、关闭应用并重开同一对话后，答案、当前题目和未交卷状态得到恢复。
3. 作答页面及其进程间通信初始化数据不包含答案、解析或评分细则；用户提交前的答案变更不触发 Cyrene 请求。
4. 用户确认交卷后，只发起一个批改轮次，提交数据与 `examId` 对应；批改失败可对已保存快照重试。
5. 单选、多选、判断、填空、简答和解答题都能被 JSON Schema 校验并以对应控件呈现；分页跳题不会丢失答案。
6. 完成批改后，成绩和复盘能关联回原试卷；原有 `pop_quiz` 与日常练习流程保持原用途。
