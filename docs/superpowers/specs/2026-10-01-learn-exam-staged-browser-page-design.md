# Learn 分阶段出卷与内置浏览器答题页设计

## 目标

让 Cyrene 先确定试卷题型与题量，再分题型生成题目，减少整份试卷一次性生成时的题型偏差和字段校验失败；完整试卷通过校验后，在右侧内置浏览器中打开一张独立的本地答题网页，用户完成答题并交卷后，再由新一轮读取答案并批改。

## 用户已确认的范围

- 出卷采用“先蓝图、再按题型生成、最后校验发布”的分阶段流程。
- 蓝图先在聊天中展示并由用户确认，再创建正式试卷草稿。
- 交互式答题页作为右侧内置浏览器的新标签打开，不再作为右侧工作区的独立检查器标签。
- 模型只生成结构化试卷数据；答题页使用应用自带模板，不执行模型生成的 HTML。
- 保持交卷与批改分轮：用户交卷时冻结答案，下一轮再读取答案并批改。
- 技能文档同步说明模型应遵循的蓝图、分题型写题、校验发布和交卷批改流程。

## 现状与问题

- `learn_exam_create` 接收整份试卷。其题目数组曾通过 `oneOf` 表达六种题型，模型容易混用单选 `correctIndex` 与多选 `correctIndexes`；校验失败时还会返回其他题型的分支错误。
- 已有主进程试卷存储和交卷 IPC（进程间通信），能够隐藏参考答案、保存答案、冻结交卷内容并通知聊天端启动批改。
- 正式答题页目前由 `ChatPageInspector` 作为工作区标签直接渲染 `LearnExamPanel`。它不是浏览器加载的页面，与内置浏览器的标签、地址栏和页面生命周期分开管理。
- 内置浏览器目前只接收 HTTP/HTTPS 地址；网页内容通过启用沙箱、隔离上下文且不暴露 Node.js 的 `WebContentsView`（网页内容视图）加载。它不能直接访问主应用的试卷 IPC。
- 项目已有基于 Electron `protocol.handle` 的本地静态资源协议实现，可作为打包页面资源服务的模式参考。自定义协议处理器必须注册到实际承载该页面的 Electron session（会话）上。
- `learn-exam-preview.html` 是独立样稿，正式答题页另有一套组件与样式，因此容易产生外观偏差。

## 设计

### 1. 分阶段出卷工具

#### 阶段 A：计划与配额

保留用户确认步骤。确认后调用计划工具创建隐藏草稿，传入试卷标题、学科、时长、满分，以及按题型分组的题量、分值和考察目标。工具检查题型、正整数题量、分值配额和满分之和，返回 `draftId`、题型配额与待完成数量。

计划中的题型为单选、多选、判断、填空、简答和解答。计划工具不接收题干、选项、答案或评分细则，避免模型在这一阶段提前生成整卷。

#### 阶段 B：按题型追加题目

提供字段互不冲突的题型工具：

- `learn_exam_add_single_choice`：选项数组与单个 `correctIndex`。
- `learn_exam_add_multiple_choice`：选项数组与 `correctIndexes` 数组。
- `learn_exam_add_true_false`：布尔型标准答案。
- `learn_exam_add_fill_blank`：空格参考答案与对应评分细则。
- `learn_exam_add_written`：简答或解答题的参考答案与 rubric（评分细则）；两类题的字段结构相同。

每个工具只允许写入自身题型，按题型配额限制题量与分值。单次可提交同类型的一批题，成功后返回该类已完成数量、剩余数量及累计总进度。批次先整体校验再写入，失败时不留下半批数据。重复写入不得悄悄覆盖已有题目；错误需指向具体题目与字段。

#### 阶段 C：完整性校验与发布

最终发布工具检查所有题型数量、各类分值配额、试卷总分、题目字段、答案索引范围和空白答案等约束。任何项目不符时，试卷保持隐藏草稿并返回可修复的问题；全部通过后才物化正式试卷记录并发布“试卷已就绪”事件。

模型收到发布成功结果后，告知用户右侧已打开试卷并结束本轮。交卷前不得读取答案或展开答案解析。

### 2. 隐藏草稿生命周期

- 草稿与 `conversationId`、创建它的出卷运行相关联，不能被交卷、批改或答题 IPC 当作正式试卷读取。
- 用户只会看到完成发布的试卷；创建中、题目不完整或校验失败的草稿不打开答题页。
- 发布成功后生成现有正式试卷记录，后续答案保存和批改继续复用现有存储契约。
- 未完成草稿设置过期清理，避免中断或失败的出卷长期残留。实施时沿用现有用户数据目录下的文件存储方式，不引入数据库。

### 3. 右侧内置浏览器答题页

- 正式试卷在 BrowserPanel（右侧浏览器面板）的内部标签栏中新增本地答题页标签，自动激活该标签；外部网站标签继续独立保留。
- 内置浏览器加载应用打包的固定静态页面，使用受控自定义协议 `cyrene-exam://paper/<examId>`。协议只映射到随应用打包的考试页面及静态资源；`examId` 经过格式和当前会话归属校验。模型只提供 JSON（JavaScript 对象表示法）题目数据，不能指定页面脚本、CSS（层叠样式表）或 HTML。
- 内部答题页使用独立 Electron session 创建 `WebContentsView`，保持 `nodeIntegration: false`、`contextIsolation: true`、`sandbox: true` 和 `webSecurity: true`，并只给此类视图加载专用 preload（预加载脚本）。普通网站继续使用现有 session 和不带 preload 的视图。
- 专用 preload 只暴露 `getExam`、`saveAnswer`、`saveNavigation`、`submit` 和状态订阅等最小 API。主进程校验调用来自登记过的内部答题页视图、URL 中的 `examId` 与会话归属；普通网页不能调用这些 API。内部页面的导航只允许保持在 `cyrene-exam://` 下，不允许打开新窗口或跳转外网。
- 不把答案或标准答案放在浏览器 URL 中。答题页通过受限 API 读取公开题目、保存作答、保存导航状态和提交试卷；参考答案、rubric（评分细则）和解析只在提交后由主进程批改工具读取。
- 打开内部考试页时不修改或清除普通浏览器的 cookie（网页会话数据）。内部页使用独立 session，不与网站共享 cookie。关闭浏览器标签只关闭页面，不删除已保存试卷；重开时按会话和试卷编号加载现有记录。
- 浏览器返回和前进在内部单页中禁用，刷新重新从主进程加载最新状态，关闭保留试卷记录。内置浏览器的加密标签快照允许保存经过格式校验的考试页 URL；应用重启恢复标签时仍通过内部页专用 session 和 preload 加载。
- 继续复用现有的题目导航、单题显示、自动保存、标记待检查、确认交卷与评分展示行为，并使正式页面与已确认样稿在布局和公式表现上保持一致。

### 4. 技能流程

更新 `skills/cyrene-exam-paper/SKILL.md`，写清楚：先拟蓝图并请求确认；确认后创建计划；按配额调用匹配题型的工具分批写题；根据工具返回的进度补齐缺失题；发布校验成功后告知用户打开了右侧答题页并结束本轮；用户交卷后在新一轮读取冻结答案、批改并保存结果。技能只引用已经实现的工具名和字段，不指导模型输出 HTML。

## 失败处理与边界

- 题型工具不匹配、题量超额、点数超额、字段缺失或索引越界时，返回精确的题型、题号与修复说明，不让模型根据其他题型的分支报错猜字段。
- 批次写入和最终发布分别具备原子性；发布失败不得显示部分试卷。
- 草稿过期后不可被旧 `draftId` 继续修改或发布。
- 关闭或切换浏览器标签不影响已经自动保存的答案；交卷必须先完成待保存答案的 flush（写入完成），并冻结一次提交内容。
- 内部答题页只允许读取当前会话拥有的试卷；任何来自地址栏、消息或不可信页面的 `examId` 都必须经主进程校验会话归属。
- 用户提供的题干和选项作为文本及受限公式标记渲染，不能解释为可执行 HTML 或脚本。

## 验收标准

1. Cyrene 能先创建含题型数量、分值和目标的蓝图，并等待用户确认后再生成题目。
2. 每种题型只能通过对应工具写入；单选/多选字段契约清楚，填空题不会被提示补选择题字段。
3. 每个题型工具返回配额进度；缺题或分值不符时无法发布，且错误能定位到题型/题号。
4. 完整试卷发布后，右侧内置浏览器自动出现并激活本地答题页标签；页面不是普通网页的 `WebContentsView` 获得主应用通用权限。
5. 浏览器标签切换、刷新、关闭或应用重启后，正式试卷与已保存答案仍按持久化规则保留；普通网页标签和 cookie 不受影响。
6. 答题页视觉与已确认样稿一致，涵盖纵向题目导航、单题内容、公式显示、进度、保存反馈、交卷确认和批改结果。
7. 用户交卷后答案被冻结；Cyrene 只能在新一轮读取提交内容，保存批改结果后答题页显示成绩和建议。
8. 技能文档中的流程、工具名、字段名与实际实现一致。

## 非目标

- 不让模型生成整页 HTML、CSS 或 JavaScript。
- 不实现通用浏览器自动化或改变现有 browser-control 工具。
- 不让模型在同一调用中生成全部题型与整份答案。
- 不改变用户答题和 Cyrene 批改分属两轮的产品行为。
- 不引入第三方考试框架或数据库。

## 实施涉及区域

- Learn 出卷工具、运行级隐藏草稿存储与正式试卷发布校验。
- 内置 BrowserPanel 标签模型、内部考试页呈现和受限主应用数据通道。
- 右侧考试模板、状态刷新、保存与交卷流程，以及浏览器标签持久化。
- `skills/cyrene-exam-paper/SKILL.md` 的出卷及批改流程。
- 对分阶段工具、草稿权限与生命周期、浏览器内部页、用户答题和交卷批改的定向验证。

## 验证约束

实施阶段需要覆盖题型配额与字段错误、草稿发布原子性、内部页面会话隔离、刷新后作答保留、交卷冻结及评分回显。实现完成前不得宣称这些场景已验证。
