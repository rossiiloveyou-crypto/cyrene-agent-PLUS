# 群聊语料采集（group-corpus）

> **状态**：已上线，纯采集层。自学习模块（T1 注入 / T2 纠错）尚未开工。
> **定位**：给排期在后面的「群聊风格自学习」攒原始数据。现在先攒，是因为代码还在改，
> 等到要做的那天不一定还能顺手捞到这些消息。

---

## 一、它是什么

一个**只写不读**的旁路采集器：把 QQ 群聊与私聊里每条消息记成一行 JSONL，放进用户数据目录。

它**不做**以下任何一件事 —— 这是它当前的全部价值所在：

| 不做 | 为什么这个"不做"很重要 |
|---|---|
| 不被任何函数读取内容 | 唯一读入口是 `corpusStats()`，只被测试使用 |
| 不注入任何对话 | 模型看不到它，所以它的存在不会改变昔涟的任何一句话 |
| 不进任何 prompt / 记忆 / 工具 | 生产代码里只有 NapCat 适配器 import 它 |
| 不含任何 LLM 调用 | 零 token 成本、零延迟影响 |

有测试锁住这几条：`src/main/corpus/group-corpus-isolation.test.ts`。

## 二、数据在哪

```
%APPDATA%\live2d-cyrene\group-corpus\
  543627098\                    ← 一个会话一个文件夹
    2026-09-21.jsonl            ← 按天分片，追加写，永不截断
    2026-09-22.jsonl
  1055799748\
    2026-09-21.jsonl
  2914636187__private\          ← 私聊：对方 QQ 号 + __private 后缀
    2026-09-21.jsonl
```

**命名规则**：群聊 = `<群号>`，私聊 = `<对方QQ号>__private`。
加后缀是为了让同号的群聊与私聊不会写进同一个目录（群号和 QQ 号同为数字，可能相等）。

**每行一条消息**（`GroupCorpusEntry`）：

```json
{"t":"2026-09-21T14:03:22.145Z","kind":"group","gid":"543627098","uid":"2914636187","uname":"BeiKia","msg":"今天天气不错","mid":"1234567","trig":"observe","allowed":true}
{"t":"2026-09-21T14:05:01.000Z","kind":"private","gid":"2914636187","uid":"2914636187","uname":"BeiKia","msg":"私聊里说的话","mid":"1234568","trig":"respond","allowed":true}
```

| 字段 | 含义 |
|---|---|
| `t` | 消息时间（ISO）。取 OneBot 事件时间，缺失时用当前时间 |
| `kind` | `group` = 群聊，`private` = 私聊 |
| `gid` | 群号（`kind=group`）或对方 QQ 号（`kind=private`）。裸值，与 transcript 的 `speakerId` 约定一致 |
| `uid` / `uname` | 发言者 QQ 号 / **当时的**群名片快照（会变，所以每条都记） |
| `msg` | 正文；纯附件消息是 `[图片]` / `[表情]` / `[语音]` / `[视频]` / `[文件]` / `[卡片]` |
| `mid` | OneBot 消息 id，用于去重 |
| `trig` | `respond` = 这条把昔涟叫起来了；`observe` = 她只是看着 |
| `allowed` | 该会话是否放行（群 = 在白名单/区块内；私聊恒为 `true`，见下） |

**`trig` 与 `allowed` 是给将来过滤样本用的**，采集期不过滤（不丢信息，将来想怎么筛都行）。

## 三、三道防删保护

语料是**只增不减的长期资产**，被清空等于前功尽弃。所以：

1. **物理隔离**：放 `userData` 顶层，与 `channels/` 平级。
   `channels/history/` 和 `channels/archive/` 都是 `MEMORY_TARGETS` 成员，会被整目录 `rmSync`；
   `history` 热文件还会在超过 200 行时截断。语料两样都不沾。
2. **显式登记**：`MEMORY_PRESERVED`（`src/main/memory/memory-deletion.ts`）里登记了 `group-corpus/`。
   那个数组存在的意义就是「让边界可被测试锁定，而不是靠注释」。
3. **回归测试**：`memory-deletion.test.ts` 锁「没被删」；
   `group-corpus-isolation.test.ts` 锁「内容一字没动」+「保留名单与删除名单路径互不包含」。

> ⚠️ **将来给自学习模块加清理逻辑时**：清理语料必须是独立操作，**绝不能加进 `MEMORY_TARGETS`**。
> 那会让「清空记忆」顺手动掉语料，也会让保留名单与删除名单的互斥测试直接变红。

## 四、采集范围与取舍（已拍板）

| 问题 | 决定 | 理由 |
|---|---|---|
| 记哪些群 | **所有群，不过白名单** | 将来把某个群加进白名单时，它之前的历史已经在攒了 |
| 私聊 | **也记** | 目标是收集「真人怎么说话」，私聊同样是真人语料 |
| 私聊的被拒消息 | **不记** | 私聊没有"旁观"一说。陌生人的 spam 若也记进来会污染语料 —— 所以私聊只记放行的，`allowed` 因此恒为 `true` |
| 重复投递 | 去重（OneBot 10 分钟窗口 + 模块内 24h `mid` 记录），命名空间是 `<kind>:<id>` | 重复行会污染将来的词频统计；群号与 QQ 号可能相等，所以命名空间必须带 kind |
| 保留期限 | **不删**，只提供 `corpusStats()` 统计 | 先收集，清理策略等真要用了再定 |
| 附件 | 记一行占位 | 保留「这个时间点有人发了图」的事实 |
| 会话名 | **不拼**（目录名只有 id） | OneBot 消息事件不带群名/昵称；宁可不拼，也不拿发言者昵称冒充 |

**私聊的先天限制**：只收得到**对方发来的**消息。昔涟自己发出去的不入语料
（两处入口都以 `self_id` 过滤掉了），所以私聊语料是**单向**的 ——
能学到对方的说话方式，学不到「昔涟在这一轮是怎么回的」。

**量级估算**：每会话每天几百条 ≈ 100 KB/天 ≈ 35 MB/年/会话。

## 五、接线位置（改动前必读）

唯一调用点：`src/main/channels/adapters/qq/napcat-adapter.ts` 的 `handleEvent`。

位置在 **NapCat 内存去重之后、权限 `drop` 分支之前**，但"在 drop 之前"只适用于群聊：

```
classifyQqEvent（拿到 respond/observe/drop）
  ↓
NapCat 内存去重（10 分钟窗口，键 = selfId + chatId + message_id）
  ↓
【语料采集】群聊：无论如何都采；私聊：drop 的不采
  ↓
drop 早返回 / observe 落 transcript / respond 起 run
```

三条必须同时成立的约束：

1. **在去重之后** —— 重连补投不重复入语料；
2. **群聊在三个分支之前** —— 未加白群的闲聊也要采，否则「将来加白名单」时前面的话全没攒下；
3. **私聊必须排除 drop** —— 私聊没有旁观语义，被拒的消息（陌生人 spam / 黑名单）
   记进来就是污染语料。

**去重键必须带 chatId**（这是实测踩到的坑）：`message_id` 只在单个会话内唯一，
群 A 与群 B（或群与私聊）完全可能发出同一个 id。只按 `selfId + message_id` 做键，
后到的那条会被当成重复而**静默丢弃** —— 表现为"消息偶尔少了，但没有任何报错"。

**代价**：这里拿不到 `normalizeOneBotMessage` 的成果（在下方且会 await），
所以正文和附件占位都要自己从 segments 抽一遍（`textFromSegments` +
`describeSegmentAttachments`）。

采集点整体包在 try/catch 里，**任何失败只打一行 warn，绝不影响消息投递与回复**。

## 七、怎么确认它在工作

1. 群里随便发条消息；
2. 看 `%APPDATA%\live2d-cyrene\group-corpus\<群号>\<今天>.jsonl` 是否多了一行；
3. 或调用 `corpusStats()` 看各群行数与时间跨度（仅测试/排查用）。

采集失败时日志里会出现 `[GroupCorpus] 落盘失败:` 或
`[NapCatAdapter] 群语料采集失败（不影响消息链路）:`。

## 八、下一步（自学习模块 T0–T3）

本层只负责「有数据」。后续设计（见会话记录）规划为：

| 层 | 做什么 | 何时做 |
|---|---|---|
| T0 | 低频蒸馏：读语料 → 产出候选风格卡（含溯源）→ 设置页人工审核 | 待排期 |
| T1 | 注入：风格卡作为**独立只读块**叠在主风格后，每群独立 + 总开关 | 待排期 |
| T2 | 纠错：n-gram 指纹拦截、标记物密度封顶、长度方差告警 | 待排期（**必须与 T1 同期上线**） |
| T3 | 自适应：新鲜度衰减、长期留存审计 | 待排期 |

**做 T0 时必须注意**：`kind=group` + `trig: "respond"` 的样本是「别人对着昔涟说话」，
语气与长度都被「在跟机器人讲话」污染了，直接拿去学风格会学歪。
样本过滤要用 `kind` + `trig` + `allowed` 三个字段，别只看正文。

`kind=private` 的样本没有这个问题（私聊本来就是一对一说话），
但要注意它是**单向**的 —— 只有对方那一半，没有昔涟的回复作为对照，
所以「哪些回复算好」这件事在私聊语料里无从判断。

## 九、T0 前置纪律：语料里的「已被擦除的人」

> **本节是 Phase 3 P3（记忆擦除）与本采集层的唯一交接口，动 T0 之前必须先读。**
> 结论先写：**擦除某个人时不删语料，一律在采样端排除。**

### 为什么不能在语料里删行

Phase 3 P3 实现了「彻底擦除某个人」（`docs/construction/phase3-p3-erasure-and-console.md`）：
删 L2 记忆、过滤 transcript、清审计/日志/备份、移除实体与关系。

**但它不碰这个目录，一个字节都不碰。** 理由：

1. **语料不影响"昔涟认不认识他"** —— 本层**只写不读、零生产消费方**（§一 的表 + `group-corpus-isolation.test.ts`），
   从不进 prompt、不进召回、不进工具。所以"他的原话留在语料里"**不会让昔涟认识他**，擦除的行为验收标准不受影响；
2. **语料是只增不减的长期资产**（§三 的三道防删保护），就地删行**不可逆**；
3. **就地删行会破坏按人分层的统计基线** —— 将来算「某人说话占比」「群内句长方差」时，
   样本被悄悄抽掉会让历史指标前后不可比。

### 所以 T0 要做的是

**采样期按排除名单跳过**，而不是改数据：

```
① 名单文件：userData/corpus-exclusions.json       ← 中性名字，见下
   { "version": 1, "entries": [ { "channel": "qq", "idHash": "<sha256(personKey) 的 hex>" } ] }
   · 只存哈希，不存 QQ 号
   · personKey 格式见 Phase 3 P2：`qq:2914636187`

② T0 逐行判定：hash(`${channel}:${uid}`) 命中名单 → 跳过该行
   · channel 恒为 "qq"（本层唯一写入方是 NapCat 适配器）

③ 永远不写回语料文件
```

### 为什么名单文件用中性名字（而不是 `group-corpus-exclusions.json`）

`group-corpus-isolation.test.ts:119-131` 的守卫是：**除 `src/main/corpus/` 外，没有生产文件可以出现带引号的精确字面量 `"group-corpus"`**（正则 `/"group-corpus"/`）。

严格说，`"group-corpus-exclusions.json"` **不会**被这条正则命中（它要求引号紧跟在 `group-corpus` 之后）。但名字仍然建议中性：

- 一旦有人写成 `path.join(root, "group-corpus")` 或引入 `corpusDir()`，守卫立刻变红 —— 而那条守卫保护的正是你攒的语料，**不该为了一个名单文件去碰它**；
- 名单属于**记忆擦除**的产物，不属于语料命名空间，放在 `userData/corpus-exclusions.json` 让归属一眼可辨。

> 顺带提醒：那条守卫的牙齿不止这一颗 —— 还有「生产代码里只有 NapCat 适配器 import 它」（`:106-117`，比对 `from ".../corpus/group-corpus"`）与「保留名单/删除名单路径互不包含」（`:82-94`）。任何"顺手把语料接进某个链路"的动作都会在这里被拦下。
