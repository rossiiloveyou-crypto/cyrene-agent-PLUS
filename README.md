## 2.2 批次 A：记忆与群聊专项（`1.2.2-PLUS`，2026-09-25）

这是本分支最大的一批改动，把「群聊理解」与「长期记忆」重做了一遍，并新增了一个**看得见、删得掉**的记忆控制台。

### A1. 群聊：她终于知道「谁在说话」

| 群里的消息 | 上游 1.2.2 | 本分支 |
|---|---|---|
| 没 @ 她、也没命中触发词 | 直接丢弃 | **记下来（旁听）** 并进入上下文，但**不回复、不打扰** |
| @ 了她 / 命中触发关键词 | 回复（但看不到前文） | 回复，且**能看懂前面大家在聊什么** |
| 不在白名单的群 | 丢弃 | 丢弃（不变） |

- **说话人归属**：请求与上下文**都带说话人标记**（`[小明]: 大家好`），不再出现「不知道谁说的裸消息」；**私聊表现逐字节不变**；旧格式群聊记录仍能正确解析。
- **不重复占上下文**：旁听内容按「滑动窗口 + 旁听块」两类分开喂入，同一条消息只出现一次。
- **温层归档**：群聊记录超出热层窗口后按月归档留存（**不进入上下文**，不额外耗 token），溯源时可读。
- **可调条数**：设置 → 记忆 → 群聊上下文 → 消息条数（3~50，默认 10；只有「旁听」消息计入）。

### A2. 记忆区块：记忆不再串味

**区块 = 一个记忆域**。同一区块内的会话共享长期记忆，不同区块之间**互不可见**。入口：**设置 → 记忆区块**。

| 概念 | 说明 |
|---|---|
| `desktop`（root 区块） | 唯一、不可删、自动包含全部桌面对话，另外最多挂 1 个 QQ 私聊 |
| 自定义区块 | 自己新建，往里放群聊 / 私聊；一个会话同一时刻只属于一个区块 |
| 独立域 | 未加入任何区块的外部会话，自成一体 |

解决的实际问题：

| 上游的串味 | 本分支 |
|---|---|
| 群 A 聊过的事，她在群 B 里说出来 | ✅ 群 A / 群 B 分属不同区块，互不可见 |
| 群里出现你的 `[用户画像]` `[近期状态]`（含私人偏好） | ✅ 画像默认**只注入 desktop 区块**，自定义区块默认关闭 |
| 群里陌生人的一句话被写成「你的事实」 | ✅ 群聊 / 独立域只能产生 L2 事件碎片，不污染画像 |
| 桌面当天话题从「最近日记摘要」漏进群里 | ✅ 摘要按「区块 + 日期」分桶存放 |

**加群 = 加白名单**：把群号加入区块即视为加入白名单；区块卡片新增「**手动加群**」（QQ / NapCat 填 5~12 位群号，QQ 官方机器人填群标识），**旧的群白名单仍然兼容放行**（微信与飞书没有群白名单概念，故「手动加群」只开放 QQ 渠道）。

### A3. 记忆管理控制台：看得见，才删得准

**设置 → 记忆 → 记忆管理**，三个视图：

| 视图 | 按什么分组 | 你会看到什么 |
|---|---|---|
| 按人 | 一个外部账号（形如 `qq:10001`） | 「🗣 他的记忆 N 条 · 👥 别人提到他 M 条 · 共 T 条 · S 个来源会话」——两个数字分开给，一眼看出「彻底擦除」删多少、留多少 |
| 按域 | 记忆区块 / 独立域 | 按容器分组，可单条勾选或批量删除 |
| 按会话 | 来源会话 | 按来源会话分组，名称取群名 / 昵称 |

- 每条记忆可看：**时间 · 来源会话 · 原话片段 · 状态**；压缩总结标注「由 N 条子条目合成」。
- **溯源**：一键跳回原始聊天记录的**那一行（含前后各 2 行）**，归档层一并查找。
- 五种删除粒度：**单条 / 批量 / 按容器 / 按人（局部）/ 按人（彻底擦除）**；删除后给出明细，并列出**级联清理**了多少证据、向量、DMAE 状态、冲突日志、悬空指针。
- 升级前遗留的旧记忆会以「**来源未知**」单列一组，不会被误删。

### A4. 「彻底擦除一个人」：四步，全程可控

```
① 预演（只看不删） → ② 手动输入「彻底擦除」四字确认 → ③ 执行（12 步流水线） → ④ 报告
```

- **预演**逐项列出：将删除 N 条（他说的 / 他的私聊 / 关联压缩总结）、**保留 M 条「别人提到他」**（附例子）、涉及哪些会话（含**她提及他的回复行数**）、同时清理的外围载体、**有意保留**清单、**疑似残留**清单（不自动修改，交人工确认）。
- **二次确认**要求手动输入四个字「彻底擦除」，严格相等才放行；点取消**不执行任何删除**。
- **防呆**：预演之后他又说了新话 → 弹「需要重新预演」并**中止本次擦除**（不会拿过期清单乱删）。
- **不需要重启**（这是它和「删除全部记忆」最大的体验差别）。

**会被清理的 13 类痕迹**（覆盖「他说过的、他私聊里的」一切来源）：

| # | 痕迹 | 处理方式 |
|---|---|---|
| 1 | 记忆本体 | 记忆、证据、DMAE 状态、冲突日志、悬空指针、反思日志（逐条级联） |
| 2 | 向量库 | **记忆向量 + 对话向量**两条通道都清 |
| 3 | 逐轮聊天记录（热层） | 群聊**逐行过滤重写**（别人的话一行不动）；他的私聊整个会话删除 |
| 4 | 按月归档（温层） | 同上 |
| 5 | 渠道审计 | 逐行过滤 + 删除文件名含他账号的日志文件 |
| 6 | 运行日志 | 逐行过滤 |
| 7 | API 调试日志 | **整份销毁**（含每次模型调用的完整 prompt 正文） |
| 8 | 记忆备份 | **整份销毁**（留着就能从备份把他「变回来」） |
| 9 | 对账备份 | 整个目录销毁 |
| 10 | 实体图谱 | 按名字精确删节点与关系（候选名单预演时先给你确认） |
| 11 | 关系日志 | 按人删除（唯一「每一轮都进主聊天」的载体） |
| 12 | 外部会话观察 | 只删他的私聊记录（群记录保留，它是区块成员选择器的数据源） |
| 13 | agent 运行记录 | 按会话过滤（含逐字对话正文） |

**明确保留的 6 类**：群聊语料（只增不减、从不进上下文，擦除连路径都不碰）、桌面对话、访问控制配置、记忆区块与成员、运行评审 / 工具输出（不自动删，但进「疑似残留」清单）。

**「她的复述」也一起删**：只删「他说的」等于没删 —— 实测中她仍可能复述已删事实。本分支的判据有两条（预演与执行同源）：**按名字**（正文含他的别名）+ **按轮次配对**（这一行的上一行就是他的行）。第二条必须有：实测泄漏的那一行一个字都没提他，只按名字匹配它会活下来。

实测修复效果（真实数据副本上跑真实代码）：

| 项 | 擦除前 | 擦除后 |
|---|---|---|
| 群聊记录总行数 | 48 | 11 |
| 他说的行 | 17 | **0** |
| 她复述 / 回复他的行 | 23 | **3**（−20） |
| 泄漏句残留 | 10 | **0** |
| 别人的行 | 8 | **8**（一行不少） |

### A5. 顺带修掉的记忆可靠性问题

| 问题 | 影响 | 现在 |
|---|---|---|
| 删了一条记忆，向量还在 | 被删记忆仍可能被召回命中 | ✅ 级联删除覆盖向量、证据、DMAE 状态、冲突日志、悬空指针、压缩总结、反思日志 |
| 「对话向量」完全不在清理范围 | 擦除后仍能从对话向量通道命中他 | ✅ 两条向量通道都清；预演与报告里新增「对话向量」一格 |
| 「删除全部记忆」不删记忆备份 | 点完磁盘上仍躺着完整旧 `memory.json` | ✅ 备份与对账备份一并销毁 |
| 记忆判定（judge）每次都超时 | 超时一次 = 那一批对话**全部不落记忆** | ✅ 超时 30s → 120s（实测单次约 49s） |
| 记忆输出被截断 | 一条候选约 700 token，两个话题以上会切断 JSON → 整批丢失 | ✅ 输出预算 800 → 32768 |
| 群聊记忆预算被浪费 | 模型把输出花在注定被丢弃的画像上 | ✅ 非主人域在提示词层只允许输出事件碎片 |
| `write_memory` 写入的记忆追不回会话 | 来源字段是空串 | ✅ 已修复 |
| `cyrene-runs/` 边界未定义 | 里面是逐字对话正文，却既不在可擦清单也不在保留清单 | ✅ 运行记录按会话过滤；运行评审与工具输出明确保留并进残留清单 |
| 「新建区块」「重命名区块」弹窗乱码 | 整段标记铺满面板 | ✅ 已修复 |
| 全新的群无法加入 | 白名单输入框整合后，没说过话的新群无路可走 | ✅ 补上「手动加群」 |
| 昵称里的 `]` 打穿说话人解析 | 群里留下残片并污染记忆原文 | ✅ 已修复（26 条特殊昵称实测全部干净） |

### A6. 有意保留的边界（如实说明，避免误解）

1. **「别人提到他」的记忆默认保留** —— 那条记忆往往同时是别人的经历（「我和小明去看漫展」），删它等于替别人抹掉他自己的事；系统单独列出交你决定。
2. **画像与关系日志里的「文本级提及」不会自动修改** —— 没有归属字段，只能按名字匹配产出「疑似残留」清单，人工确认后编辑（误改的代价高于漏改）。
3. **群聊语料一个字节都不动** —— 只增不减且从不进入上下文，留在语料里不会让她「认识」谁。
4. **旧版本擦除留下的、一个字都没提他的孤儿回复**结构上无法定位，既删不掉也列不进残留；**首次就用本版擦除没有这个问题**。
5. **`memory-trace.log` 会记录「删除动作」本身**（谁、何时、删了多少条），但**不记录被删正文** —— 有意保留的审计载体。
6. **「他的行数归零」是擦除那一刻的断言** —— 他之后再来找她说话，自然会有新记录（不做黑名单，从零重新认识）。
7. **本次未改动召回侧** —— 「别人提到他」的记忆在召回时仍可能被她当作「我听说过他」引用，这条在后续版本规划中。

## 2.3 批次 B：白名单与权限重做（2026-09-20）

改动前，「一个 QQ 号能做什么」被拆成**三处配置、三种语义**：设置页的私聊白名单 / 群号白名单 / 群员白名单，加上控制台的「工具调用白名单 + 三档 mode」。加一个人要在两个窗口各加一次，群里的「能说话」和「能用工具」还是两套名单。

本分支统一为 **名单 + 权限位**：

```jsonc
// <userData>/channels-settings.json
{
  "schemaVersion": 2,
  "qq": {
    "allowedGroupIds": ["20001"],   // 保留：群号白名单（仍在设置页）
    "groupRequireMention": true
  },
  "toolAccess": {
    "groupMemberGate": true,        // 群员发言限制（原 groupLimitMembers，迁到控制台）
    "toolGate": true,               // 工具调用拦截（原 mode 三档压成一个开关）
    "entries": [{
      "channel": "qq", "userId": "10001", "label": "阿岚", "addedAt": 1758212345678,
      "permissions": { "private": false, "group": true, "tool": false }  // 勾选 = 授权 = 放行
    }]
  }
}
```

**行为变更（用户可感知）：**

| # | 变更 | 说明 |
|---|---|---|
| 1 | **拒绝优先** | 两个总开关默认**全开**、名单默认**为空**：名单外的账号私聊被丢弃、群里即使 @ 了她也被丢弃（写 `message_blocked` 审计）；**新增账号默认只勾「群聊」** |
| 2 | **群聊准入** | `@ 昔涟 / 命中触发词 → 群号白名单 → groupMemberGate 开启时校验该 QQ 在名单里且勾了「群聊」→ 交给 dispatcher`；关掉 `groupMemberGate` 等价于旧的 `groupLimitMembers: false` |
| 3 | **私聊准入** | 在名单里且勾了「私聊」才放行；私聊**没有**总开关，和改动前一样始终强制校验 |
| 4 | **工具调用** | `toolGate` 关闭 → 不拦（审计记「未检查」）；开启 → 名单里且勾了「工具」才放行，否则 `[拒绝]` + 审计。**变化点：旧 `mode: "groups"` 下私聊工具调用是不拦的，现在私聊也必须勾「工具」权限** |
| 5 | **拦截文案** | 指向「聊天窗口 → 控制台 → 白名单与权限」 |

**配置迁移（Breaking，且旧名单不迁移）：**

- 新增 `schemaVersion`，读到 `< 2`（含完全没有该字段的老文件）时 **`toolAccess.entries` 整体置空**，旧私聊 / 群员 / 工具白名单条目**全部丢弃**；`saveChannelsSettings()` 会写入 `schemaVersion: 2`，**迁移只发生一次**。
- 设置页**删除**两个 textarea（私聊 QQ 白名单、放行群员 QQ 白名单）与「启用群员发言限制」开关，只保留「群号白名单」，并补一行说明指向控制台。
- 控制台区块重做为「**白名单与权限**」：两个总开关 + 列表项两行结构（`渠道 · 账号 · 备注 · 已授权标签 · [权限] [移除]`），点「权限」就地展开三个勾选框；详情页「白名单」字段改称「权限」（已授权 / 未授权 / 未检查）。

**升级后必须做的事**：控制台名单为空且「群员发言限制」默认开启 → **必须重新添加账号并勾权限**（QQ 填 QQ 号；群号白名单仍在设置页）。

## 2.5 升级前必读（有数据影响）

### ⚠️ 会看到一次「记忆格式升级」弹窗

启动 `1.2.2-PLUS` 时若检测到旧版记忆，会提示：**旧记忆无法自动迁移，将被清空**，两个按钮 `清空记忆并继续` / `退出应用`。

- 选「退出应用」→ **一个字节都不会动**；
- 想留旧记忆：先退出，备份 `%APPDATA%\live2d-cyrene` 目录，再启动并选择清空。

| 会被清空 | 会被保留 |
|---|---|
| 画像（L0/L1）、事件碎片（L2）、向量索引、关系日志、实体图谱、朋友圈与社交原子、世界书运行时状态、**渠道聊天记录（热层 + 按月归档）**、对账备份 | 桌面对话记录、渠道与模型配置、记忆区块配置、表情包、定时任务、插件、**群聊语料** |

> 💡 **为什么不做自动迁移**：旧记忆里没有「这条是关于谁的」字段，结构上无法回溯；按人浏览 / 按人擦除必须建立在带归属的新数据上，所以选择**清空重建**。
>
> 另外：升级闸门清空记忆后 `memory.json` 是懒创建的，**不会立刻出现**，直到第一次写入才落盘 —— 这是正常现象，不是清空失败。

### 其他注意事项

- **白名单**：批次 B 会**一次性清空**旧白名单，需要重新添加账号（见 [2.3](#23-批次-b白名单与权限重做2026-09-20)）。
- **重启**：「删除全部记忆」沿用上游行为**需要重启**（会提示「立即重启 / 稍后」）；**「彻底擦除一个人」不需要重启**。
- **数据兼容**：旧群聊记录 ✅ 正常读取；旧群白名单 ✅ 兼容放行（UI 不再写入，想清理请手工编辑 `channels-settings.json`）；无归属的旧事件碎片 ✅ 保留并显示为「来源未知」；桌面对话 / 配置 / 定时任务 / 插件 ✅ 不受影响。
- **回滚**：代码可以回滚，但**记忆清空与擦除不可逆**。回滚后旧版会忽略新字段、不报错，但已清掉的旧记忆不会回来 —— **升级前请自行备份 `%APPDATA%\live2d-cyrene`**。另：把 `schemaVersion` 改回 `1` 会**再次触发清空**，不要用它来降级。

## 2.6 版本号说明

`1.2.2-PLUS` 是**合法的 SemVer 预发布版本**（`-PLUS` 是 prerelease 标识段）：

- 应用内显示、`electron-builder` 的 `artifactName: Cyrene-Setup-${version}.${ext}`、`app.getVersion()` 都按字符串直出，**打包不受影响**；
- 但按 SemVer 排序规则 **`1.2.2-PLUS < 1.2.2`**。若某个渠道已发布过正式版 `1.2.2`，**不要把 `1.2.2-PLUS` 当作同分支的更高版本推给自动更新**（客户端会判定为「比你当前版本旧」而不升级）；
- 推荐做法：把 `1.2.2-PLUS` 作为**独立分发的加强版**（Releases 单独说明），下一次常规发布从 `1.2.3` / `1.3.0` 继续递增。

# 三、怎么用这个分支

**前置条件、安装步骤、打包方式与上游完全一致** —— 请直接看 [README.upstream.md](./README.upstream.md) 或上游仓库的「🚀 快速开始」（Windows 10/11 64 位、Node.js 24 LTS、npm 10+、Rust stable、VS 2022 Build Tools）。

```powershell
npm install
npm run dev              # 开发模式（改主进程代码需重启 Electron）
npm test                 # vitest run
npm run build            # 主进程 + preload + cli + renderer
npm run package:win:dir  # 打未打包的 Windows 目录版（完整安装包见上游文档）
```

**与上游同步（如果你想自己继续跟进）**：

```powershell
git remote add upstream https://github.com/Playa-0v0/Cyrene-Agent.git
git fetch upstream
git merge upstream/master     # 或 git rebase upstream/master
```
